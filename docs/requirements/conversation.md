# 会话与过程状态需求

> 角色：需求　类型：功能　状态：草案（2026-10-21，待评审；先文档、后实现）

## 0 背景与目标

当前会话区把“本轮进度”放在消息流里（`WorkingRow` 跟着消息滚动），头部只有 `Agent · project · 模型`；没有固定的状态条、没有 token/速度、没有按消息类型区分的颜色。  
目标是把它做成类似 **Pi Agent TUI** 的体验：

- **固定状态条**：位置不动，内容每秒/每事件自动刷新；
- 用户发出消息后，能看到 **n/4 大步骤 + 子状态 + 耗时**；
- 完成后能看到本轮/会话的 **token、上下文占比、速度**；
- 用户/助手/思考/工具/失败等消息类型有稳定、可区分的视觉编码；
- 状态条不因消息滚动、流式更新而跳动。

## 1 场景

| 场景 | 期望 |
|---|---|
| S1 发送（无会话） | 1/4 发送 → 建会话 → 2/4 受理 → 3/4 模型处理，状态条固定 |
| S2 工具调用 | 3/4 子状态变为“执行 read…”；不增加大步骤 |
| S3 重试 | 3/4 子状态“Ns 后重试（i/max）”；倒计时；状态条保持位置 |
| S4 完成/失败/中断 | 4/4 完成/失败；显示耗时、token、速度；失败原因可展开 |
| S5 用户上翻 | 停止自动跟随；状态条仍固定；可回到最新 |
| S6 切换会话 | 状态条重建：当前会话最后状态/最后回合摘要，不残留上一个会话 |
| S7 长会话/压缩 | 显示上下文占比、窗口；压缩后未知时显示 `?`，不编造 |
| S8 重开页面 | 从会话文件恢复最后一轮 usage/context，显示“上次回合”摘要 |

## 2 功能需求

### FR-1 固定状态条

- 位于**消息滚动区与输入框之间**，不随消息滚动；
- 桌面高度约 44px；窄屏可换行成两行，不裁切；
- 任何会话状态（空、运行、完成、失败）都占同一位置，避免布局跳动；
- 不是 Toast、不放在 header、不叠在消息上。

### FR-2 四个大步骤

- 固定 `n/4`：发送消息 → 受理请求 → 模型处理 → 完成；
- 工具调用、思考、输出、重试都是 3/4 的**子状态**，不增加 n；
- 每步有稳定名称；4/4 显示完成/失败/已中断；
- m=4 由产品状态机定义，不依赖模型计划。

### FR-3 计时

- 状态条只显示**耗时数字**（如 `18s`，从发送开始），不加“本轮”前缀，也不同时显示“本阶段”；用户已经在当前会话里，“本轮”是冗余；
- 工具耗时由工具块自己的 `durationMs` 显示，状态条不重复；
- 每秒刷新，但只刷新状态条，不重渲染消息列表；
- 阶段切换**不重置**本轮时间；
- 重试倒计时逐秒减少；中断/完成后停止。

### FR-4 Token / 上下文

**符号约定（必须有 tooltip/图例，不能裸用）**：

| 符号 | 含义 | tooltip |
|---|---|---|
| `↑` | 会话累计输入 tokens | “会话累计输入 tokens” |
| `↓` | 会话累计输出 tokens | “会话累计输出 tokens” |
| `◔` | 上下文占用 | “上下文占用 X% / window” |
| `⚡` | 上一轮输出速度 | “上一轮输出速度；输出 N tokens，首字 Xs” |

> 触屏没有 hover：状态条必须提供可点击的 `?` 图例入口，不能只靠 title。


- 本轮：input、output、cache read/write（有则显示）、cost（有则显示）；
- 会话累计：至少 input/output 总量；
- 上下文：`percent / contextWindow`；未知显示 `?`；
- 精确值只能来自 Pi `usage` / `getContextUsage()`；没有就显示 `—` 或 `≈`，不编造。

### FR-5 速度

- **TTFT**：请求开始到首个流事件；
- **输出速度**：完成后用精确 output tokens / 生成时长；
- 运行中可显示 `≈` 估算（按已输出字符/4 与时间），必须标 `≈`；
- 没有首 token/usage 时显示 `—`。

### FR-6 消息类型视觉

- 用户、助手、思考、工具执行中/成功/失败、错误、重试、系统/压缩摘要，各有稳定样式；
- 颜色/背景/边框只来自 tokens；不新增页面级任意色；
- 思考用弱化文本；工具成功/失败不只用文字，也有背景/图标；
- 对比度满足 WCAG；颜色不是唯一信息载体。

### FR-6.1 消息类型背景色

| kind | 背景/样式 | 不能只靠颜色 |
|---|---|---|
| user | 深色气泡（`ink-900` / 自定义 `message-user-bg`） | 右侧对齐 + 气泡 |
| assistant | 透明/正文 | 左侧阅读列 |
| thinking | `sunken`/弱化斜体 | “思考”标签/折叠 |
| tool-running | `sunken` + accent spinner | “执行中” + 工具名 |
| tool-done | `success-soft`/success | “完成” + 结果 |
| tool-error | `danger-soft`/danger | “出错” + 错误文本 |
| failure | `danger` 文本/`danger-soft` | 归类原因 + 原始错误 |
| system/compaction | `sunken`/muted | 系统标记 |

- 每个消息块根节点必须有 `data-message-kind`（user/assistant/thinking/tool-running/tool-done/tool-error/failure/system）；
- 颜色只来自 tokens；相邻类型背景必须不同；对比度 ≥ WCAG；
- Playwright 断言：各 kind 的 computed background 至少两两不同；失败/成功/运行中可区分。

### FR-7 自动跟随

- **判定**：`distanceToBottom = scrollHeight - scrollTop - clientHeight`；小于 60px 视为“贴底”；
- **贴底**：新消息/流式增量到来时，`scrollTop = scrollHeight`（容器内滚动，`behavior:auto`，不用 smooth 以免流式抖动）；
- **上翻**：用户主动滚离底部后，新增内容**不改变 scrollTop**；状态条仍固定；可提供“回到最新”；
- **发送**：发送时强制回到贴底；
- **状态条**：在滚动容器外，测试要求滚动 500px 后它的 `getBoundingClientRect().top` 不变。
- **文案**：不用 `↑/↓` 箭头；会话累计写“输入 / 输出 / 上下文”；状态条不出现“本轮”前缀。

### FR-8 完成/失败摘要

- 完成：4/4 + 耗时/tokens/速度；
- 失败：4/4 + 失败类别 + 原始错误（可展开）+ 重试/重发入口；
- 中断：4/4 已中断 + 已完成部分 usage（若有）。

### FR-9 会话切换与恢复

- 切会话：状态条立即清空/重建，不显示上一个会话数据；
- 从历史加载：能显示最后回合的 tokens/context/耗时；
- 运行中切换：不打断原会话，返回时恢复运行态。

### FR-10 后端数据

- `GET session` 的 meta 增加 usage/context（或单独接口）；
- `done`/`error` SSE 带本轮 usage 快照；
- 运行中可发 `usage`/`turn` 事件；没有就不发，不造；
- 数据源：Pi assistant `usage`、session entries、`getContextUsage()`。

### FR-11 性能

- 状态条计时器独立，不触发消息列表重渲染；
- SSE 高频 delta 不导致状态条整页重排；
- 长会话消息 memo；不测量 DOM 布局。

## 3 非目标

- 不做任务计划/任意步骤（m 固定 4）；
- 不做多 Agent 聚合仪表盘；
- 不做历史成本图表、预算告警；
- 不在 provider 不提供 usage 时伪造精确 token；
- 不改模型调用策略；不改 prompt。

## 4 验收

- 1280/768/375 下状态条位置固定、不横向溢出、不遮输入框；
- 发送→受理→模型处理→完成的 n/4 顺序正确；工具不增加 n；
- 计时每秒更新，只显示耗时数字；完成/中断后停止；
- tokens/context 与 Pi usage 一致；未知显示 `—`/`?`/`≈`；
- 用户上翻后 scrollTop 不变；状态条 top 在滚动前后不变；
- 状态条不出现 `↑/↓` 和“本轮”前缀；
- 消息 kind 的 computed background 两两不同；
- 消息类型在截图和 DOM 上可区分，颜色均来自 tokens；
- 单测覆盖 reducer/格式化；Playwright 覆盖固定位置、步骤、计时、usage、切换会话。

## 5 开放问题

1. 状态条放“输入框上方”还是“聊天 header 下方”？建议输入框上方（离操作近、固定）。
2. 本轮 token 显示 input+output 还是分列？建议“输入/输出”文字，窄屏只显示总量。
3. 运行中速度是否显示估算？建议显示 `≈`，完成后再显示精确值。
4. 会话累计是否默认显示？建议折叠在 tooltip/展开，不占主行。
