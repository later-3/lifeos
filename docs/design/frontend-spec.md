# 前端设计与交互规范（统一规范）

> 角色：设计规范　类型：统一约束　状态：实施中（2026-10-20 重构）
>
> **所有页面遵守本文。** 页面专属的数据、关系、交互、状态写在 `docs/design/<page>.md`，不写在这里。
> 数值只来自 `frontend/src/design/tokens.css`；控件只来自 `frontend/src/design/`；布局宽度只来自 `design/layout.ts`。
> 历史与反例进 cases/flywheel，不在本文堆过程记录。

## 0 两条原则

1. **参考优先**：`docs/standards/reference-baseline.md` 里有类似场景的，采用它记录的“借什么/不借什么”；
2. **自主设计**：参考里没有的，先想清楚数据、关系、交互，再实现；不凭“看起来差不多”补。

## 1 数据模型（系统层）

```
Life OS（~/.lifeos）
├─ 系统配置 config/（models/settings，跨 Agent，不属于任何 Agent）
├─ 通用层 interaction-harness/（协议/规范/飞轮/概念/任务类型）
├─ agents/
│  └─ <agentId>/
│     ├─ Agent { id, name, defaultProjectId, defaultSessionId, avatar }
│     ├─ memory/（Agent 记忆，跨项目）
│     └─ projects/<全局 projectId>/（绑定：sessions、daily、cases、todo、agent 的项目记忆）
└─ projects/<projectId>/（全局项目：project.json、项目共享记忆、规范）
```

- **Agent N:M Project**（通过绑定目录；同一项目可被多个 Agent 绑定，一个 Agent 可有多个项目）；但**当前页面的 Agent → Project 是 1:N**；
- **Agent × Project 1:N Session**（会话属于某个 Agent 的某个项目绑定）；**Session 1:N Message**。
- 具体页面展示哪些实体、哪些关系，写在页面文档，不在这里重复。

## 2 视觉基础

**数值只在 `tokens.css`；本节只写角色、选择规则和可用档位，不写第二套数值。**

| 角色 | 用途 |
|---|---|
| `surface` / `sunken` / `hover` / `line` | 表面靠背景差分层；`line` 只做细边界 |
| `ink-900` / `ink-700` / `ink-500` / `ink-300` | 正文/标题 → 次级正文 → 辅助信息 → 分隔线/图标；`ink-300` 不承载文本 |
| `accent` / `accent-soft` / `accent-line` | 只给主操作、选中态、焦点；不做装饰性彩色 |
| `danger` / `danger-soft` / `success` | 只给危险/成功语义，不做品牌装饰 |

| 字阶 | 用途 |
|---|---|
| `micro` | 元信息、行内标记、列头；不承载长文本 |
| `meta` | 表单标签、辅助说明 |
| `body` | 默认正文/控件 |
| `content` | 长正文/阅读内容 |
| `title` | 页面/区块标题 |

- **间距**：4px 网格；常用档位 4 / 8 / 12 / 16 / 20 / 24 / 32。页面用 primitive/布局类，不写任意值。
  - 状态条/指标组：**图标↔数值 4px；输入↔输出等同组 8px；不同指标组 12px**；不要用一个平均 gap 把层级抹平。
- **尺寸/命中区**：WCAG 2.5.8 最低 24×24；WCAG 2.5.5 / Apple HIG 44×44；Material 48×48。
  - 项目规则：**主操作 / 分区导航（Tab）≥44×44**；次级密集控件 `sm` 28 / `md` 36；WCAG 24 只是法律下限，不用于主导航。
  - **可达性**：分区切换不得用左上角小胶囊；用全宽 Tab 栏或侧栏，避免要求用户做精确横向瞄准（Fitts）。
  - 自动检测：`ui-contract` / design audit 扫 `role=tab` 与主操作目标：高 ≥44；全宽 Tab 的单项宽度至少占内容区 40%。**axe 只抓 24 下限，抓不到 44 的舒适区，必须用项目规则补。**
- **圆角**：`inner` / `control` / `panel` / `bubble` / `full` 五档，不按页面新造。
- **动效**：只保留“正在工作”等有语义的反馈；遵守 `prefers-reduced-motion`；页面不写 `transition-all`。

## 3 布局

- 整体骨架、列宽、折叠成本、面板上限、聊天保底**只由 `layout.ts` 计算**；组件不再算第二套宽度。
- 列可独立收起/展开；任一列收起只占一条 44px 全局导航轨，成本与列数无关。
- 拖宽方向由把手位置决定（右缘 +1，左缘 −1），不按 key 名猜。
- 右侧面板互斥（文件面板/完整历史同时最多一个）；面板要宽度时，只临时收左列，不静默吞点击。
- 窄窗口放不下时，左列转浮层抽屉，聊天列不被压破；放不下就明确降级，不静默消失。
- 列头只写“这一列是什么”；计数、默认、时间等行内数据只出现一次，不在列头重复。

### 3.1 布局与参考（写代码前）

页面功能明确 ≠ 布局明确。每个新页面/模态先回答：

1. **页面类型**：个人资料编辑 / 设置 / 列表-详情 / 模型选择 / 空态 / 其他；
2. **同任务参考**：找 2–3 个真实产品做同一件事，记录在 `reference-baseline.md` 的“场景行”；写“借什么/不借什么”；
3. **线框与区域顺序**：先画线框（ASCII 可），确定 header / 主内容 / 次内容 / 操作区；
4. **交互模型**：哪些是立即生效、哪些按保存、切分几个保存域、切换用全宽 Tab/侧栏/单页滚动；
5. **视觉角色**：颜色/字号/间距只映射到 tokens，不把参考产品的品牌色搬进来；
6. **状态矩阵**：加载/空/错/脏/保存中/成功。

**硬规则**：没有“页面类型 + 至少一个同任务参考 + 线框”不写代码；参考是借结构/交互，不是抄皮肤。

- **两段内容优先单页**：只有 2 个设置分区、且一页滚动能容纳时，优先单页分区，不硬上 Tab；只有 3+ 分区、或任务/保存域确实无法同页时，才用全宽 Tab/侧栏，并在页面文档写明理由。
- **单实体 vs 多实体**：单 Agent/单对象编辑用“顶部资料 header + 单页 sections”；左栏只在“多 Agent 列表/多分区导航”时有意义。把单个头像/单个 profile 放进左栏 = 浪费空间。
- **参考优先级**：同任务场景优先；不因为“某产品很酷”就借。AI Agent 资料页优先看 LobeHub/Grok/OpenAI/Claude；GitHub 这类账号设置是反例（死板、分区重），不作为首选。
- **参考必须可核**：产品名 + 实际页面/官方文档链接 + 借什么/不借什么；不写“某产品大概这样”。
- **布局决策矩阵**：页面类型 / 信息量 / 保存域 / 同任务参考 → 列 2–3 个布局方案 → 用户拍板；不靠实现者直觉。
**自动检查**：目标尺寸/全宽导航/溢出；**人工评审**：信息层级、分组、鼠标移动距离（Fitts）。参考行只进 `reference-baseline.md`，不建第三份参考清单。

## 4 数据呈现与关系

- **1:1**：字段组/设置区，标签在上、值在下；不拆成多列。
- **1:N**：列表/下一列/详情区；父级给出子项计数；子项有独立空态和新建入口；不使用弹窗把层级压平，除非是短操作。
- **N:M**：标签/chips、多选、关联表；明确“当前选中”和“可添加”。
- **层级**：树、面包屑、可展开行；层级深时给当前位置，不只给图标。
- 列表/表格：行内数据只出现一次；数字列用 tabular-nums；长文本 truncate/line-clamp；日期/数字用 `Intl.*`。
- 空态、加载态、错误态是数据呈现的一部分，不是事后补丁。
- 页面文档必须写清：本页有哪些实体/字段、关系是什么、为什么这样表达。

## 5 通用交互

- **操作分层**：每个页面/单元最多一个主操作；立即生效的动作（如头像上传）必须单独标出，不能藏在“保存”语义下。
- **动作挂在被作用的对象上**：作用于消息的动作在消息动作条；作用于“这一轮”的进度/失败在回复侧。
- **可见性**：悬停出现的动作在触屏/无悬停设备常显；反馈期间保持可见；不挤布局。
- **保存/脏/关闭**：有未保存改动时，关闭必须确认或保留草稿；不允许静默丢弃。
- **加载/错误/空**：加载中禁用会写数据的操作；失败给原因和出口；空态给下一步动作。
- **删除/危险操作**：确认或可撤销；不用 `window.confirm`。
- **反馈**：保存中/成功/失败要有状态；Toast 不替代会话内留痕。
- **键盘/焦点**：对话框焦点陷阱、Esc、初始焦点；Tab 顺序可见；焦点环不能被 `outline-none` 去掉。

## 6 组件 / primitive

- 页面只组装 `design/{ui,overlay,toast,rail}` 的 primitive；不自己画按钮/模态/表单/空态。
- 新控件先落 `design/`（变体、尺寸、disabled、focus-visible、命中区一次做全），再加断言，最后进页面。
- 组件不写任意值、不写裸调色板、不写 `outline-none`。

## 7 内容与可访问性

- 文案用用户语言：按钮用动词（“保存基础信息”），错误说“发生了什么 + 怎么恢复”，不把 `agent.json`/`identity.md` 这类实现路径放主界面。
- 状态条/数据文案：符号/图标必须带 `tooltip` 或图例；裸的 `↑/↓` 不允许，但“符号 + tooltip”可以（`↑` 输入、`↓` 输出、`◔` 上下文、`⚡` 速度）。当前会话内不再加“本轮”前缀。
- 空态/错误态文案属于设计内容，不是占位。
- 表单控件有 label/可访问名；图标按钮有 `aria-label`；Tab/Dialog 按 WAI-ARIA APG；对比度满足 WCAG。
- 装饰图标 `aria-hidden`；异步提示用 `aria-live`。

## 8 交互模式

模式是“一类页面/单元的通用解法”，**不是独立文档库**。页面文档引用模式名，只写本页差异。

| 模式 | 何时用 | 必需区域/状态 |
|---|---|---|
| `modal-form` | 短表单、配置弹窗 | 标题/说明、表单区、footer 主次操作；加载/错误/脏/保存中/成功 |
| `resource-index` | 列表/集合管理 | 页头标题+操作、筛选/排序、列表、行内动作、空态/加载/错误 |
| `resource-details` | 单个实体的查看/编辑 | 页头、主内容、次要信息、保存/取消、脏提示 |
| `settings` | 分组配置 | 分组标题/说明、字段、保存状态；分组间不混 |
| `profile-editor` | 头像/名字/简介/身份等资料编辑 | 头像锚点、称号/简介分组、一个主保存、头像立即生效；参考 Instagram/GitHub/OpenAI 资料编辑 |
| `settings-sections` | 2+ 个独立保存域的设置 | header + 全宽 Tab/侧栏/单页分区；保存跟随分区；窄屏不压破 |
| `model-picker` | provider/model/thinking 选择 | 服务→模型→档位联动；显示当前默认与支持档位；参考 OpenAI/Claude/VS Code |
| `empty` | 无数据 | 一句解释 + 主操作；不堆装饰 |

- 第一次使用某个模式：在页面文档写“模式草案”（区域/状态/交互），不建独立文件；
- 第二次被其他页面复用：再抽成 `docs/design/patterns/<id>.md`，两个页面改为引用；
- 模式变化时，检查所有引用页面。

## 9 验证与约束

提交前必须全绿：

```bash
pnpm typecheck && pnpm lint:tokens && pnpm test && pnpm test:ui && pnpm build
```

| 闸 | 拦什么 |
|---|---|
| token | 任意值、裸调色板、`outline-none` |
| primitive | 页面自绘控件、同一控件多实现 |
| 契约 | 布局不变量、对比度、命中区、键盘/焦点、模态语义 |
| 截图基线 | 视觉悄悄变化；变化必须人眼确认，不能直接刷掉 |

- 视觉变化：`pnpm test:ui:update` 后必须看 diff；基线更新单独提交。
- 截图只比骨架：会话正文、历史正文用 `data-shot-mask` 遮罩，避免真实数据漂移。
- 页面自检：没有任意值、没有页面级控件、没有未登记的 `outline-none`。
- 具体命令与门禁实现见 `AGENTS.md` 与 `frontend/test/ui-contract.mjs`；本文只写规则，不复制脚本。

### 9.1 开发检查点（五类，按顺序）

| # | 检查点 | 何时 | 具体做什么 | 失败处理 |
|---|---|---|---|---|
| 1 | **意图 / 数据·关系 / 模式** | 写代码前 | 页面文档写背景、用户任务、主操作/立即生效、明确不做；写数据（实体/字段/来源）、关系（1:1/1:N/N:M/层级及表达）、交互；选模式并写差异 | 没写不写代码 |
| 2 | **WIG** | 合并前 | 用 Vercel Web Interface Guidelines 审改动：表单 label/name/autocomplete、焦点、错误、文案、反模式；输出 `file:line` | P1 必修 |
| 3 | **APG / WCAG + axe** | 合并前 | Tab/Dialog 按 WAI-ARIA APG；axe 无 serious/critical；键盘走查 | P0/P1 必修 |
| 4 | **Playwright 状态/数据** | 合并前 | 加载未完成禁写、接口失败有出口、脏关闭不丢、保存中、375/768/1280 无溢出 | P0/P1 必修 |
| 5 | **NN/g + 截图** | 新页面/新模式 | 三宽度截图；选 5–6 条 NN/g；证据 + 结论；人签字 | 不签字不算完成 |

来源：WIG `https://github.com/vercel-labs/web-interface-guidelines`；APG `https://www.w3.org/WAI/ARIA/apg/`；axe-core；NN/g 10 heuristics；WCAG 2.5.8/2.5.5、Apple HIG、Material 3、Adobe Spectrum（目标尺寸）。

**边界**：点 1 负责“数据是什么、关系是什么、怎么展示/交互”的设计；点 2–5 只验证呈现与行为，**不替代数据模型/关系评审**。

检查点 2–5 是**开发门禁**，不是设计文档；页面文档只登记本页要验证的具体项。

## 10 页面文档模板

每个页面/模态/独立面板一份 `docs/design/<page>.md`，按以下顺序。

**“意图 + 模式”是同一份页面文档的必填内容，不拆成两个文档：** 意图 = 背景/用户任务/主操作/立即生效/不做；模式 = 本页选用的模式 + 本页差异。第一次使用写在该页的“模式草案”里，第二次复用才抽到 §8。

1. **背景与意图**：页面名、入口选择器、结构单元、代码文件、使用方、为什么需要；用户任务、主操作/立即生效动作、明确不做；
2. **数据**：实体/字段/来源/刷新/权限/空值/长值；
3. **关系**：1:1 / 1:N / N:M / 层级；怎么表达；为什么；
4. **用户任务**：主任务/次任务；
5. **交互**：查看/选择/下钻/创建/编辑/删除/搜索/筛选/排序/确认/撤销；键盘/焦点；
6. **布局与参考**：页面类型、2–3 个同任务参考（借什么/不借什么）、线框/区域顺序、密度、响应式；引用哪个模式；
7. **状态**：加载/空/错/脏/保存中/成功；每个状态三选一：已实现+断言 / 未实现+`docs/todo.md` 行 / N/A+原因；
8. **内容与可访问性**：文案、错误/空态、label/role/键盘；
9. **模式与实现**：引用模式 + 本页差异 + primitive；
10. **设计验收**：可观察行为，不写测试实现；
11. **范围外**：明确不做什么。

**背景是硬要求**：只靠文件名，别人不知道它对应哪个页面。
