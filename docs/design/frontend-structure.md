# 前端结构设计（数据 · 呈现 · 交互）

> 角色：设计　类型：结构定义　状态：实施中（v5 · token + primitive + 单轨折叠 + 布局数学单一入口，2026-10-18）
>
> **视觉与工程约束不在本文，在 `docs/design/frontend-path.md`**（token 唯一来源、primitive 层、四道门禁与验收命令）。
> 本文只描述"数据长什么样、界面由哪几块组成、每块的形式从哪来"。
>
> **折叠（v5）**：收起态合并成一条 **44px 全局导航轨**（`design/rail.tsx`），任一列收起都只占 44px、全展开为 0；此前"每列各留 36px 图标轨"的做法已废弃——三列全收要吃掉 108px，且宽度数学按 20px 计算，实测把聊天列压到 252px（低于当时声明的 `MIN_CHAT=300`）。
> **布局宽度**：唯一来源 `design/layout.ts` 的 `layout()`；面板上限、聊天保底（420px）、窄视口自动降级都由它决定，`test/ui-layout.test.mjs` 穷举断言。
> **列头与行内的职责分离（2026-10-18 用户指出）**：列头只写"这一列是什么"（助手 / 项目 / 该列所属项目名），**不放徽标与计数**；"默认"、会话数、时间等属于行内数据标记，只在行里出现一次。判定：同一个信息若已在行内可见，列头重复即为噪音。
> **视觉**：数值来自 `design/tokens.css`（灰阶四档按对比度选定：ink-500 = 4.83:1）、控件来自 `design/ui.tsx`；accent 只给主操作与选中态，侧栏靠背景色差（`bg-sunken`）分层而不靠满屏边框。

## 0 两条原则（用户 2026-10-17 定）

1. **参考优先**：`references.md` 里的参考项目有类似做法的，**采用它们的形式**；
2. **自主设计**：参考里没有的，站在我们这边想清楚——**数据关系、数据本身、怎么交互**，再实现。

## 1 数据：具体有哪些、什么关系（系统层，多 Agent 出发）

```
Life OS（~/.lifeos）
├─ 系统配置 config/（models/settings——跨 Agent，不属于任何 Agent）   [本轮不上界面]
├─ 通用层 interaction-harness/（协议/飞轮/概念/任务类型）            [本轮不上界面]
├─ 项目共用层 projects/<pid>/（同一项目跨 Agent 共享）               [本轮不上界面]
└─ Agents/（注册判据 = agent.json，枚举 = 扫描；多 Agent 是设计出发点）
   ├─ Agent { id, name, defaultProjectId, defaultSessionId, avatar(auto=按 id 推导) }
   │   ├─ SSE 流：一条流覆盖该 Agent 的全部会话（seq 单调、since 续传）
   │   └─ Projects/（注册判据 = project.json；内置 workspace 为默认）
   │       └─ Session（JSONL；标题 = session_info 重命名 > 首句；出厂默认会话用 defaultSessionId 标记）
   │           └─ Message → blocks：text / thinking / toolCall（toolResult 挂回对应调用）
   └─ 其余 Agent 同构
```

- 会话操作：新建（POST）、重命名（PUT → Pi `session_info`）、删除（DELETE，运行中 409）。
- **本轮明确不上界面**（数据在文件、无接口）：identity、harness 内容（todo/cases/daily）、模型与提示词配置、外部项目注册、跨 Agent 运行状态聚合、流式过程中的工具/思考实时事件。

## 2 呈现与交互（每一块形式都标来源）

| 区域 | 形式 | 来源 |
|---|---|---|
| **整体骨架** | **三级级联菜单**（从左到右依次挨着展开）：第1列 Agent 整栏 → 第2列 该 Agent 的 Projects → 第3列 该项目的所有事情 → 主区聊天；点上一级，下游整列切换 | **用户自主设计**（2026-10-17 拍板；形态≈访达列表视图） |
| 每列 · 折叠 | **完全独立**（收第2级不牵连第3级，2026-10-17 用户更正）：列头 40px，右侧 28px 图标钮收起；被收起的列进入**左侧 44px 全局导航轨**（每个收起层一个图标钮，带 tooltip；窗口太窄被自动收起时按钮 disabled + 说明）。收起成本与层数无关 | 用户自主设计（独立性）+ **Cherry / VS Code 的 activity bar 形态**（v5 由"每列 36px 轨"改为此） |
| 每列 · 拖宽 | 列间 1px 分隔线拖动（悬停微亮、夹紧区间），宽度存 localStorage，刷新不丢 | **Pi Web 可拖侧栏**（参考项目，`pi-sidebar-width` 同思路） |
| 整体视觉 | 单色克制：neutral 灰阶、选中项白卡（shadow-sm + ring-1）、圆角 rounded-lg/xl、1px 细分隔、transition-colors、焦点 focus-visible ring；**无彩色点缀、无花哨动效** | 参考项目共性 + 用户“好看≠花哨”要求 |
| 第1列 · 助手列表 | 头像（id 推导色阶+首字母）+ 名称，选中高亮；点选级联下钻（自动选默认 project + 最近会话） | **LobeHub 助手栏** + 用户级联规则 |
| 第2列 · 项目列表 | 行内**只写目录名**；右侧固定槽位常显会话计数、hover 原地换成「从该助手移除」（不位移）；**不标注“默认”**（与运行点语义冲突）；空态统一 EmptyState | 自主设计（v5 简化：列头不重复行内数据） |
| 第3列 · 会话列表 | 标题、相对时间、运行点、悬停操作（✎重命名 / ✕删除）；底部「＋新建会话」；空态提示 | **Pi Web SessionSidebar**（会话操作与展示） |
| 主区 · 头部 | 44px：左为**会话标题**（body 500）与次级 meta `Agent · project`（micro/ink-500），右为文件面板开关 | 自主设计（v5 恢复上下文显示；此前误删面包屑曾导致全列折叠后无法判断身处何地） |
| 会话显示链 | `session_info.name`（出厂预置 **welcome to lifeos**、行内 ✎ 可改名）‖ 首条用户消息（后端返全文、UI 截 50）；**无兜底**（无名无首句即空白） | **Pi Web SessionSidebar 链**（去掉其 id12 兜底，用户 2026-10-17 定） |
| 主区 · 消息 | 阅读列 `max-w-reading` 居中；**用户与助手都渲染 Markdown**（marked + DOMPurify，禁 HTML 透传）；用户消息深色气泡（含反白 md 样式）、助手消息无气泡贴白底；思考/工具折叠块带状态点 | **Pi Web MessageView** + Cherry 的"单侧气泡"对比法；Markdown 复用文件面板同一条已装依赖链路 |
| 主区 · 流式 | 增量追加进文本块；空块显示 `…`；**仅在贴底时自动跟随**（上翻不被抢滚动）；完成后按接口全量刷新 | 自主设计（SSE 契约 §11） |
| 新建/空态 | 底部"＋新建会话"；空态统一 `EmptyState`（图标 + 一句解释 + 主操作），列表加载用 skeleton | primitive 层（`design/ui.tsx`） |

**交互场景**：切换 Agent（重置流游标重订、定位该 Agent 最近会话）· 选会话（载入消息）· 新建 · 重命名（prompt）· 删除（confirm，删当前则定位最近）· 发送/流式/打断态沿用事件流。

**首开定位**：进该 Agent **最近的会话**（全新安装只有一条 → 出厂默认会话）。

## 3 逻辑关系的表达结论

1. Agent 是**第1列整栏**（多 Agent 系统事实，可切换）；
2. Project **升格为独立的第2列**（原“分组头”方案作废——用户 2026-10-17 改为级联；第3列 = 该 project 名下的所有事情，会话先行，将来任务/todo 挂同列）；
3. "默认"只存在于数据层（`defaultProjectId`/`defaultSessionId`/`isDefault`）；**界面不呈现徽标**——行里只写名称。"默认"用点表示会与"运行中"绿点语义冲突，用文字会与列头重复（2026-10-18 用户三次要求简化）；
4. 消息的逻辑结构（思考/工具/结果/文本）由服务端按 Pi 真实内容块装配，前端只渲染。
