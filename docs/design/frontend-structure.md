## 1 数据：具体有哪些、什么关系（系统层）

```
Life OS（~/.lifeos）
├─ 系统配置 config/（models/settings——跨 Agent，不属于任何 Agent）   [本轮不上界面]
├─ 通用层 interaction-harness/（协议/飞轮/概念/任务类型）            [本轮不上界面]
└─ agents/（枚举 = 扫描 agent.json；出厂只有一个 Agent）
   ├─ Agent { id, name, defaultProjectId, defaultSessionId, avatar(auto=按 id 推导) }
   │   ├─ SSE 流：一条流覆盖该 Agent 的全部会话（seq 单调、since 续传）
   │   └─ Projects/（**目录即项目**；外部项目才有 project.json 记 path；内置 workspace 为默认）
   │       └─ Session（JSONL；标题 = session_info 重命名 > 首句；出厂默认会话用 defaultSessionId 标记）
   │           └─ Message → blocks：text / thinking / toolCall（toolResult 挂回对应调用）
   └─ 多 Agent（新建/删除）与跨 Agent 共享项目 = 未实现，见 docs/todo.md
```

- 会话操作：新建（POST）、重命名（PUT → Pi `session_info`）、删除（DELETE，运行中 409）。
- **本轮明确不上界面**（数据在文件、无接口）：identity、harness 内容（todo/cases/daily）、模型与提示词配置、外部项目注册、跨 Agent 运行状态聚合、流式过程中的工具/思考实时事件。

## 2.1 一轮对话的呈现：左侧是"回复"，右侧是"消息"

> 2026-10-20 与用户逐条对齐。这一节写**出发点**，不写死实现细节：以后流程变了，按这里的出发点推演，并同步改代码与本文件。

### 出发点（三条）

1. **发出即进入"回复侧"**：用户按下发送，对他来说消息已经发出去了，接下来左边就该出现"这一轮正在发生什么"。左侧承载的是**这一轮**（进度、步骤、结果、失败），不是"某条消息"。
2. **失败也是一种回复**：模型超时、后端挂了、工具没结果——都要在左侧写清楚"在第几步、因为什么"。把失败提示塞在用户消息下面就错了：那看起来像用户自己说的话有问题，且看不出是哪一步断的。
3. **动作挂在被作用的对象上**：复制/重发作用于**用户消息**，就放在用户消息的动作条里；"这一轮失败/正在做什么"作用于**这一轮**，就放在左侧。两侧不混。

### 左侧本轮槽：从发送到结束

| 阶段 | 触发事实 | 左侧显示 |
|---|---|---|
| 发送中 | 前端 `fetch` 未返回 | 旋转 + 「发送中…」+ 计时 |
| 已受理 | 后端 202 | 「已受理，等待开始」 |
| 等待模型 | 收到首个流事件前 | 「正在连接模型…」（<3s）/「等待模型响应…」+ 计时 |
| 重试中 | Pi `auto_retry_start` | 「模型调用失败，Ns 后重试（i/max）：原因」+ **逐秒倒计时**（Pi CLI `RetryStatusIndicator` 同款） |
| 思考 / 工具 | `thinking` / `tool_execution_start` | 「思考中…」/「正在执行 <工具>…」+ **本步耗时 · 本轮总耗时** |
| 输出 | `delta` | 「输出中…」+ 计时 |
| 完成 | `done` + 重读会话 | 最终回复（思考/工具块保留可展开） |
| 失败 | `error` / 会话里的 `stopReason` | **第 N 步失败：<归类文案>** + 原始错误小字 + 过程详情 |

**失败时展开过程**：失败轮次的思考块**默认展开并保持展开**（工具块跑完本来就不收），让人看见"它到底做了什么、卡在哪"。更完整的"过程详情面板"（Pi Web `ProcessDetailsGroup` 那种逐段列表）暂不做——现在失败行 + 展开的块已经能解释。

### 失败归属：哪一步出错，显示什么

| 步 | 失败 | 判定事实 | 显示（左侧） |
|---|---|---|---|
| 1 发送 | 前端请求失败（断网/4xx/5xx） | `fetch` 抛错 / `!response.ok` | 「发送失败：<原因>」（可重试；不回填成"模型失败"） |
| 2 建会话 | 新建会话失败 | `POST …/sessions` 非 2xx | 「无法开始这一轮：<原因>」 |
| 3 受理 | 202 后进程消失 | 60s 无事件 + 重读仍无助手条目 | 「后端在这一轮中断（重启/崩溃），本轮没有结果」 |
| 4 模型 | 连不上 / 超时 / 鉴权 / 限流 / 5xx | `errorMessage` 归类（`src/failure.ts`） | 归类文案 + 原始错误 |
| 5 模型 | 返回空 | `stopReason=stop` 且无内容 | 「模型没有返回内容」 |
| 6 工具 | 工具出错 | `toolResult.isError` | 工具块「出错」+ 结果 |
| 6 工具 | 没拿到结果 | 无 result 且本轮已结束 | 工具块「未完成」 |
| 7 收尾 | 用户打断 / 截断 | `stopReason=aborted` / `length` | 「本轮已中断」/「回复被截断」 |

**注意**：判断"丢了"前必须**先确认后端不在跑**（`GET …/sessions/:sid` 的 `meta.running`），并且**发送时重置心跳计时**——否则"页面静置 >60s 后发送"会被立刻误判成中断（已修，见 cases C067）。推断性文案（如"受理之后中断"）只出现在**左侧**（`data-testid="turn-status"`），用户消息下不放任何失败说明。

### 用户消息动作条（右侧）

- 「复制」：内容动作，悬停出现；
- 「重新发送」：作用于这条消息；**仅当它所属的那一轮失败**时出现；与复制同一条动作条、同一套可见性规则；
- 不再放"失败说明"（那是回复侧的事）；
- 「编辑」等需要分支的动作暂缓（没有 fork 时有重复消息问题）。

### 顶部模型显示：默认 vs 覆盖

- 顶部显示**这个会话当前使用的模型**（`meta.model`）。
- **从没对本会话用过 `/model`** → 会话模型 = Agent 默认模型；**默认变了，顶部要跟着变**。
- **用过 `/model`** → 会话级覆盖（Pi 会写 `model_change`，持久）；默认再变也不影响它。
- 判定"是否覆盖"必须有**显式标记**（计划用 Pi 自定义条目 `lifeos_model_override`），不能靠"和默认值相等"猜——覆盖成同一个值也会误判。
- **实现**（`src/model-follow.ts` 纯函数 + `agent-host.ts` 接线）：保存默认 → 同步**没被覆盖且不在跑**的打开中会话，并广播 `agents_changed`（前端只刷 meta）；`/model` 写 `lifeos_model_override`；新会话写 `lifeos_default_model`（记录创建时默认）；**重开会话**时按三者判定：已是默认→不动；等于记录的默认→跟随新默认；与记录不符/旧会话无记录→视为覆盖（补 `legacy` 标记，不擅自改）。正在跑的会话不在半路换模型。

**交互场景**：切换 Agent（重置流游标重订、定位该 Agent 最近会话）· 选会话（载入消息）· 新建 · 重命名（prompt）· 删除（confirm，删当前则定位最近）· 发送/流式/打断态沿用事件流。

**首开定位**：进该 Agent **最近的会话**（全新安装只有一条 → 出厂默认会话）。

## 3 逻辑关系的表达结论

1. Agent 是**第1列整栏**（多 Agent 系统事实，可切换）；
