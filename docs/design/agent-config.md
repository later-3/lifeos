# Agent 配置（模态）

> 角色：设计　类型：页面设计　状态：v0 草案（待评审；实现差距另登记 todo）
>
> 统一规范见 `docs/design/frontend-spec.md`；本页只写本页的数据、关系、交互、状态。

## 0 背景

- **页面**：Agent 配置（编辑当前 Agent 的名称、描述、身份、头像、默认模型）。
- **入口**：左侧助手列表每行的头像按钮（`aria-label` 以“配置 ”开头，`title="配置助手"`）。
- **结构**：模态；单页：顶部 profile header（头像/名字/描述）→ 运行配置面板（模型）→ 身份编辑区；无 Tab。
- **代码**：`frontend/src/AgentConfig.tsx`；复用 `Modal`、`Field`、`Button`、`Segmented`、`controlClass`。
- **使用方**：用户在 Agent 列表里点某个助手的配置按钮。
- **为什么需要**：Agent 的名称/描述/身份/头像/默认模型需要有地方查看和修改，且修改后能立即影响该 Agent 的展示与后续会话。

### 意图

- **用户任务**：查看/修改这个助手的名称、描述、身份、头像、默认模型。
- **主操作**：footer → 保存基础信息；运行配置面板内 → 保存模型配置（同页两个独立保存域，仅 footer 一个是 primary）。
- **立即生效**：头像上传/恢复，不经过“保存”按钮。
- **明确不做**：模型目录编辑、系统级配置、身份富文本/预览、项目列表。
- **成功标准**：保存后列表/会话头部/后续 prompt 使用新值；不出现静默丢弃、空值写回或“部分成功但显示整体成功”。

## 1 数据

| 实体 | 字段 | 来源 | 说明 |
|---|---|---|---|
| Agent | `id`、`name`、`description`、`avatar`、`identity`（identity.md 文本） | `GET /api/agents/:id`、`GET /api/agents/:id/identity` | 本页编辑对象 |
| 模型目录 | `providers[]`（id/name/models）、`settings` | `GET /api/models-config` | 只读；决定可选服务/模型 |
| Agent 模型配置 | `defaultProvider`、`defaultModel`、`defaultThinkingLevel` | `GET /api/agents/:id/config` | 本页保存对象 |
| 思考档位 | `thinkingLevelMap`（模型声明哪些档位可用） | 模型目录 | 只列该模型支持的档位 |

- 头像文件由 `POST /api/agents/:id/avatar` 写入；上传/恢复后立即生效，不经过“保存”按钮。
- 身份文本上限由服务端限制（>64KB 拒绝）；前端应在提交前提示，不以服务端错误作为唯一反馈。
- 模型清单本身不在本页编辑；没有模型时只给配置路径提示。

## 2 关系与表达

| 关系 | 基数 | 表达 |
|---|---|---|
| Agent → Agent 模型配置 | 1:1 | 同页“运行配置”面板的服务/模型/思考级别三项 |
| Provider → Model | 1:N | “服务”下拉 → “模型”下拉联动 |
| Model → 思考档位 | 1:N | “思考级别”下拉，只列该模型支持项；未设置 = 跟随系统默认 |
| Agent → Project | 1:N | **不在本页展示**；属于主工作区/Agent 详情页 |

- 基础信息与模型配置在**同一页**，但保留两个独立保存域：接口与失败语义不同，不混在一个保存按钮里；页面只有一个 footer primary。
- 头像属于“立即生效”动作，和“保存基础信息”不是同一事务；界面上必须能看出这一点。
- 身份正文是长文本，使用正文排版；不用代码字体承载长 prose。

## 3 用户任务

- 改名称/描述，保存后列表与当前会话头部同步；
- 编辑身份文本（identity.md），保存后影响该 Agent 后续 prompt；
- 更换头像 / 恢复自动头像（立即生效）；
- 查看当前默认服务/模型/思考级别，修改后保存；
- 关闭弹窗；有未保存改动时不应静默丢弃。

## 4 交互

### 4.1 基础信息

- 名称：必填，trim 后为空则禁用保存；长度上限按接口。
- 描述：可选，一句话说明职责。
- 身份：多行文本；加载完成前不可保存；加载失败给错误与重试。
- 头像：选择文件（png/jpg/webp，≤2MB）→ 上传 → 立即刷新头像；有自定义头像时显示“恢复自动头像”。
- 保存：提交 `name` + `description` + `identity`；按钮在保存中禁用并显示“保存中…”。

### 4.2 模型

- 选 Provider → 模型列表切到该 Provider 的第一个模型；
- 选 Model → 思考档位只保留该模型支持的项；当前值不支持时回到“未设置”；
- 思考级别：未设置 = 跟随系统默认；保存后写 Agent 配置，不写会话级覆盖；
- 保存：三个值必须完整；没有模型时禁用保存并给配置提示。

### 4.3 通用

- 打开时应有明确初始焦点（第一个可编辑字段，而不是关闭按钮）。
- 关闭：Esc / 头部 X / footer 关闭；有未保存改动时确认或保留草稿。
- 加载：基础信息与模型目录是独立异步资源；各自 loading/error，不共用“加载中…”。
- 保存失败：显示接口原因 + 可恢复动作；两个请求部分成功时不能显示成整体成功。

## 5 布局

### 5.1 布局决策（待拍板）

- **页面类型**：`profile-editor`（头像/名字/描述/身份）+ `settings-sections`（模型作为同页设置区）。
- **同任务参考**（`reference-baseline.md` 前端页面布局）：
  - Instagram「编辑主页」：头像锚点 + 名字/简介成组 + 一个保存；
  - GitHub profile settings：资料区 + 设置分区；
  - OpenAI ChatGPT 资料/自定义指令、Claude 个性化：分区设置、说明少。
- **当前实现**：**S（LobeHub-style 单页）**；顶部 profile header + 运行配置面板 + 身份编辑区，无 Tab。
- **候选与证据**：
  | 方案 | 形态 | 证据 | 结论 |
  |---|---|---|---|
  | A | 顶部 profile header + 全宽 Tab | 过渡方案 | 仍是“切页”，模型仍被当成另一页；不采用 |
  | B1 | 左侧 profile rail + 右侧单页滚动 | 单个 profile 占据左栏 | **不采用**：单实体左栏浪费空间；LobeHub 单 Agent 页用顶部 header，不用左栏 |
  | B2 | 左侧 profile rail + 右侧分区导航 | 多分区设置才需要 | 只有两段时过重，等 3+ 分区再考虑 |
  | **S（推荐）** | 顶部 profile header（头像 72 + 名字/描述）+ 同页“运行配置”面板（模型）+ 身份编辑区；无 Tab | **LobeHub Agent Profile**：`AgentHeader` 头像+大标题，`ProfileEditor` 顶部资料区 + runtime config 面板 + prompt editor；**Grok Bot**：Name/Job/Description 三字段；ChatGPT/Claude 分区设置 | 最符合“模型配置属于基本信息”的事实 |
  | C | 顶部资料头 + 单页滚动，两段各自保存 | 无切换但两个保存按钮 | 可作 S 的变体；保存域待定 |

- **结论**：采用 **S**；B1/B2 不采用（单实体左栏浪费；只有两段时导航过重）。
- **S 的布局**：
  ```text
  ┌────────────────────────────────────┐
  │ 配置助手                        × │
  ├────────────────────────────────────┤
  │ [头像 72]  coder                   │
  │            编码/开发协作的 Agent    │
  ├────────────────────────────────────┤
  │ 运行配置                           │
  │ [服务] [模型] [思考级别]           │  ← 同页面板
  ├────────────────────────────────────┤
  │ 身份（bio 风格编辑区）              │
  ├────────────────────────────────────┤
  │ 保存后立即生效      [关闭] [保存]   │
  └────────────────────────────────────┘
  ```
- **保存**：基础信息用 footer primary；模型配置用运行配置面板内的 secondary 保存；关闭时统一 dirty 检查。

- 模态宽度 640；头部（标题 + 关闭）→ profile header（头像 72 + 名字/描述）→ 运行配置面板 → 身份编辑区 → footer。
- footer：左侧说明；右侧“关闭”+“保存基础信息”（页面唯一 primary）；模型保存放在运行配置面板内。
- 基础信息：头像行 → 名称 → 描述 → 身份（大编辑区）。
- 模型：服务 + 模型两列，思考级别整行；无模型时用空态替代表单。
- 单页滚动；profile header 与运行配置面板不折叠；身份区可滚动编辑。

## 6 状态

| 状态 | 设计要求 |
|---|---|
| 加载（身份/模型目录） | 各自显示加载；加载完成前禁止保存会写数据的操作 |
| 加载失败 | 显示错误原因 + 重试；不能永远停在“加载中…” |
| 脏 | 有任何未保存改动时，关闭前确认或保留草稿 |
| 保存中 | 保存按钮禁用并显示进行中；避免重复提交 |
| 成功 | Toast + 更新父级列表/会话头部；不能只提示成功但界面不更新 |
| 失败 | 错误原因 + 恢复动作；部分成功要明确哪部分成功、哪部分失败 |
| 空（无模型） | 显示“未解析到模型”+ 配置路径；不显示不可用的保存按钮 |

## 7 内容与可访问性

- 标签/提示用用户语言；`agent.json`、`identity.md`、`workspace/config.json` 不作为主界面说明文案。
- 无 Tab；打开时焦点进入名字输入框；Dialog 焦点陷阱/Esc；表单都有 label/可访问名。
- 隐藏的文件 input 要有可访问的上传按钮；错误提示用 `aria-live`。
- 身份文本区的 label 为“身份信息”，hint 说明用途；不让 hint 变成控件的唯一名称。

## 8 模式与实现

- 模式：`profile-editor`（顶部资料 header + 同页配置 section）；单页、无 Tab。
- **为什么不是普通 `modal-form`**：本页有两个独立保存域（基础信息/模型），还有一个立即生效的头像动作；单一表单模式会把“保存”语义压平。
- 必需区域：profile header / 运行配置面板 / 身份编辑区 / footer 主次操作。
- 必需状态：加载、错误、脏、保存中、成功；基础信息与模型各自保存。
- primitive：`Modal`、`Field`、`Button`、`controlClass`、`AgentAvatar`、`Toast`。

## 9 设计验收

- 身份/模型目录加载完成前，保存按钮不可用；加载失败有可见错误和重试。
- 修改名称后直接关闭，出现未保存确认（或草稿保留）；不能静默丢弃。
- 头像上传/恢复立即生效，且不依赖“保存基础信息”。
- 切换 Provider 后，模型与思考档位不会保留不支持的值。
- 375 / 768 / 1280 宽度下无横向滚动；单页滚动不出现横向溢出；页面只有一个 primary 操作。
- 保存失败时，界面不显示整体成功；部分成功有明确说明。

## 10 检查点（本页）

- **WIG**：footer/说明不写 `agent.json`/`identity.md` 实现路径；名称/描述有 label；焦点可见；未保存关闭有提示。
- **APG / axe**：无 Tab；Dialog 焦点陷阱与 Esc；表单可访问名；axe 无 serious/critical。
- **Playwright**：加载未完成禁保存；身份/模型加载失败有错误与重试；脏关闭不丢；保存中；375/768/1280 无横向溢出；单页无切换高度问题；页面只有一个 primary。
- **NN/g**：状态可见（加载/保存/失败）、用户语言（去掉实现路径）、用户控制（脏关闭）、错误预防（加载中禁写）、极简（去掉重复/技术文案）。
- **意图 / 数据·关系 / 模式**：§0 意图、§1 数据、§2 关系、§3–4 交互、§8 模式草案；没有就不写代码。数据/关系不靠 WIG/axe 发现，必须在写前定清楚。
- **视觉/布局/组件尺寸**：颜色/字号/圆角只来自 tokens；内容边距 20；输入/按钮高 36；profile header 头像 72 + 名字 title；运行配置同页；身份正文用 body/content；375 页面不横向溢出；只有一个 primary 操作。
