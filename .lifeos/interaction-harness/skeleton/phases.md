# phases/

阶段：开发类 A 任务的分阶段记录（协议 §3.7）。

- 每个阶段一份文件，按 P1、P2… 编号；
- 阶段文件写清：目标、每一步的规范与要达成的目的、完成后可验证的现象；
- 阶段完成后更新 `task.md` 的整体状态，不在这里记整体进度。

## 每个阶段/计划文件的必含结构（内容要求）

一个合格的 `Pn-标题.md`（或同类超前规划文件）每一步至少有六段，缺一不合格：

1. **动作**：这一步具体做什么（写到可执行的粒度，不是"做修复"）；
2. **关键契约**：端点/事件/错误码/字段表/边界语义——写到另一个 Agent 不用再问就能实现与测试；
3. **遵循规范与参考**：引用条文编号与参考出处（PR/文档行号），把"借什么/不借什么"落到实处；
4. **目的**：对应任务 01-background 的验收条或已拍板决策（可标"对应验收 N"）；
5. **测试**：测试编号（T1…）与场景（自动化/契约/手测）；
6. **对照检查**：完成后回查该步目的与完成标准——只在达成时推进；偏离记录进 log、必要时先改目标。

**收束时**：整份计划末尾要有"整体达成判定清单"，对验收条与已拍板决策逐条打勾（达成/未达成各带证据）。参考实现：任何按本结构写的 Pn 文件都可以互相对照。

上层文件（04-plan/03-phase）的骨架由任务类型模板（`task-types/<类型>/template.json`）声明；本节只管 phases/ 下的步骤级文件。
