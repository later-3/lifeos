# 任务模板（general · 普通任务）

> 协议在固定路径下，不存在"版本"概念。

**这是"普通任务"的基础内容**：既不是改产品行为，也不是改协作规范，但仍要把这件事管起来、能回看。
只放最简：`task.md` + 两份文档（背景 + 步骤）。机器模板在同目录 `template.json`；项目可覆盖。

## 1 任务清单 `task.md`（每个任务目录一份）

```md
# <任务名>

类型：general
类别：G 普通任务
状态：进行中
负责人：<agentId> ｜ 记录者：<agentId>
日期：YYYY-MM-DD
默认：否
目标：一句话（可验收）
必需文档：01-background · 02-plan
当前指针：下一步做什么 / 卡在哪
```

## 2 文档（只两份，保持简单）

| 文件 | 写什么 |
|---|---|
| `01-background.md` | 现状事实（一两句）+ 为什么做 + 完成标准（怎么算做完） |
| `02-plan.md` | 步骤（按顺序，尽量简单）+ 验收（怎么确认做到） |

## 3 判据：什么时候用 general

- 一件事要跟进/记录，但**不改产品行为**、**不改协作规范**：整理资料、调研、外部沟通、一次性操作、环境维护等；
- 想改"怎么协作/怎么做" → 用 `development` 的 **B**；想改用户可观察的行为 → `development` 的 **A**；只回答一个问题 → `development` 的 **C**。
