# 飞轮

**飞轮是思想，不是台账。** 这里只放"能滚起来的东西"：反复奏效的做法、反复踩的坑、以及为什么。

- 台账类内容（任务、清单、进度）不放这里；它们是任务记录与项目规范的事。
- 具体事实（某次发生了什么）放 `cases/`；概念解释放 `concept-space.md` + 词条文件。
- 每条尽量写成"可复用的一句 + 一个依据（案例编号或任务记录路径）"，让人能顺着查。
- **骨架/家目录类改动：模板（仓库根 .lifeos/）是唯一事实源**——文档抄模板、代码只做复制，不在代码里写第二份目录清单。（依据：2026-10-17 案例 C001/C002）
- **安装一次性、启动只校验**：任何"每次启动都写入"的逻辑，先问一句"它会不会覆盖用户改动"。（依据：2026-10-17 案例 C001）

- **设计点先拍板再动手**：出设计说明（含选项与推荐）→ 用户逐条批 → 才改代码；实现轮只执行已批清单。（依据：2026-10-17 案例 C004）
