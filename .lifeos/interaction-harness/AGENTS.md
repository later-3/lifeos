# 交互 harness · 通用层指引（骨架）

这里是**交互 harness 的通用层**（对所有项目生效）。它怎么用、由什么组成、每部分怎么维护，
**以协议正文为准**：`protocol.md`（本目录下）。本文件只写这个目录自己的规矩。

- **不要在这里复制协议正文**：协议是产品资产，仓库根 `.lifeos/` 是源、这里只是安装出来的副本；本目录**所有文件只在首次安装时写入**——家目录已存在时安装只提醒、一个字节都不改，升级协议请自行比对处理（协议 §6 加载与维护）。
- 维护入口：`flywheel.md`（思想与积累）、`concept-space.md` + 两级索引（概念）、`cases/`（正例与反例，按日期分文件）、`task-types/`（任务类型细则，按项目声明加载）。
- 新增一个词条：先在 `concept-space.md` 写清"它是什么"，再使用（协议 §4 自举）。
- 新增一个案例：写进 `cases/` 下当天的文件（一个日期一个文件），编号连续、不重写历史（协议 §5、§6）。
- 分层与归属：通用层（本目录）/ 共享 workspace / 项目共享层 / Agent 私有 workspace / Agent × 项目 / Task，见协议 §16.2。
- 规范目录统一英文 `specs/`；本目录的 `task-types/` 是模板默认层，项目/Agent 可覆盖（选一份，不合并）。
- 规范与模板不是同一件事：规范逐层追加、不覆盖；任务模板按 §16.4 选择一份。
