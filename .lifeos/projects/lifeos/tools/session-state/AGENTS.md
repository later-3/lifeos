# session-state/

会话状态的**四层核对**工具。用户报"数字对不上 / 点了没反应 / 有数字没点"时，**第一个跑它**，不要读代码猜。

## 背景与目的

2026-11-05，用户连续三次报同一类问题（"显示未读 1 但列表里没有绿点"、"正在跑但项目后面没有数字"），
我每次都零散地 fetch 几个接口、开浏览器截图、翻 `state` 文件，二十多分钟得不出结论。用户的原话：

> 每一个位置该显示什么内容，那个数字它是怎么来的。我说了不正确之后，你应该能快速收集信息，
> 判断那些数字或者数字的来源能不能对得上。如果前端展示的数字来源没问题，那前端一定能正常展示。
> 如果前端没正常展示，那是前端展示的问题；如果本身就没有这个数字，前端也没法展示。

这个工具把"判断"变成一次执行：**把同一条会话在每一层的事实并排放出来，标出第一处不一致**。

## 什么时候用

- 用户报状态类问题（点不对、数字不对、数字和点不同步、点了不消失、有数字没点）；
- 改完状态相关的代码，想知道四层是否仍然一致；
- supervisor / 定期巡检（退出码 0 = 一致，1 = 有差异）。

只改文案、只改样式时**不用它**。

## 四层是什么

| 层 | 名字 | 从哪读 | 回答什么 |
|---|---|---|---|
| L1 | `disk` | `$LIFEOS_HOME/state/session-views.json` | 落盘事实（重启后唯一能恢复的） |
| L2 | `sse` | `/api/events` 第一帧的 `running` / `unread` / `aggregate` | **服务端此刻认为的真相** |
| L3 | `api` | `/api/agents/:a/projects/:p/rows` 的 `activity.state` | 一次列表请求会返回什么 |
| L4 | `dom` | 真浏览器里渲染的徽标与点 | 用户实际看到什么 |

## 怎么判定（工具的结论逻辑）

```
L2 服务端真相 ──对不上──> L3 行对象   ⇒ 后端两条路径口径不一致（unread() vs rowActivityOf()）
L3 行对象   ──对不上──> L4 画面     ⇒ 前端渲染问题（applyRowPatch / sessionSlots / deriveStatus）
L1 磁盘     ──对不上──> L2 服务端   ⇒ 落盘/内存不一致（重启会丢未读）

四层都一致但用户看着不对 ⇒ 视觉问题（颜色/尺寸/动画不够分明），不是逻辑 bug
```

**`running` 不参与 L1 对比**：它是纯内存态，不落盘是正确设计（重启后本来就没有在跑的回合）。

## 用法

```bash
pnpm state                              # 全量（含浏览器），对着 43120
pnpm state:no-ui                        # 只查 L1-L3（快，2 秒）
pnpm state --agent coder                # 只看一个 Agent
pnpm state --session 01a1a583           # 只看一条（前缀匹配）
pnpm state --json                       # 机器可读
pnpm state --base http://127.0.0.1:43131 --web http://localhost:5174
```

环境变量：`LIFEOS_BASE`（后端）、`LIFEOS_WEB`（前端）、`LIFEOS_HOME`（家目录）、`CHROME_PATH`。

## 副作用（重要）

- **只读**：不点会话（点开会把未读标成已看，**现场就毁了**）、不发消息、不删东西、不写任何文件。
- 只读 `session-views.json`，不写。
- 退出码 `0` = 四层一致，`1` = 有差异，`2` = 连不上实例。

## 这个工具自己踩过的坑（改它之前先读）

1. **点的选择器不能按 title 正则匹配**：会命中 Task 名字「0003 生成中实时 token」（168×13）。必须加几何约束（点 ≤12px）。
2. **助手行的名字不能取 `innerText` 第一行**：那是头像字母（"F"）。取最长的一行文字。
3. **必须等行渲染齐再读**：只等第一个选择器会漏掉后面的行，"画面全 0" 是假阳性。
   判据是"DOM 行数 ≥ 服务端返回条数"，不是"等 N 秒"。
4. **`--base` 与 `--web` 必须分开**：开发实例的前端在 vite（5174），后端（43131）没 `frontend/dist` 时根本不服务页面；混用会把空页面报成前端 bug。

这四条都是"工具骗了我"，所以写在这里——**工具的假阳性比没有工具更糟**。
