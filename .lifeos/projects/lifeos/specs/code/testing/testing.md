# 测试用例规范

> 角色：架构 / 开发　类型：规范（测试）　状态：现行（2026-10-24）
>
> 场景与入口见仓库根 `AGENTS.md`；检视流程与结论分级见 `specs/review/review.md`；本文只写测试怎么写。

## 怎么用

写新用例/读老用例时对照 §2；每类门禁要能证明自己活着（遇到尸变断言要被封掉）；违反 = 缺陷。

## 2 条文

### 2.1 隔离：写只入临时家目录，真实数据只读；mock 先断言命中

- 规则：家目录用 `installHome`+`LIFEOS_HOME` 临时目录；真实用户会话/配置绝不写；route mock 需要一条"已命中"断言（防止模式写错打到真实接口）。
- 依据：案例 C051、C039、C047（验证环境不干净 → 误改真实模型）。机器检查：现有 `test/*.test.mjs` 全部临时 home 模式。

### 2.2 每个新接口至少一条非 2xx，断言 code/原因而非状态码

- 规则：不存在/非法入参/鉴权失败/打架（运行中）成套写；错误语义测试不因状态码微调而变绿。
- 依据：案例 C050（No API key 被报 404"找不到"）。机器检查：`test/api.test.mjs` 的失败分类用例。

### 2.3 配置类页面四态必测：加载/错误/脏/无数据

- 规则：依赖后端状态的界面写齐四态断言（加载未完禁写、失败有出口、脏关闭提示、空数据禁保存）。
- 依据：案例 C086（AgentConfig 保存空值/永远加载中/丢改动/空模型可保存）+ C106。机器检查：`frontend/test/ui-contract.mjs` + config 页面用例。

### 2.4 每类既有缺陷补"制造缺陷 → 门禁变红"的活性验证

- 规则：门禁门槛数目/关键项存在性可断言；改一个 token 或删一段基线时必须红；门禁脚本与实现同 commit，改脚本要写明原因。
- 依据：2026-10-18 基线段落被误删仍全绿的事故（案例详情待历史迁移补编号）。机器检查：`frontend/test/ui-contract.mjs` 自检段。

### 2.5 断言行为结果，不断言实现细节

- 规则：测试描述用户可验证的行为（"列收起后聊天不被压破"），不命中函数名/成员名等内部结构。
- 依据：仓库根 `AGENTS.md`（"针对性测试覆盖真实场景与边界"）+ 2026-10-18 体检（断言漂移教训）。机器检查：`pnpm test`。

### 2.6 结构改动三道闸一起跑：doc-links + home:check + home.test

- 规则：改 `.lifeos` 模板/结构除常规测试外必跑 `pnpm home:check`、结构链接门禁 `test/doc-links.test.mjs`；验证"说明文件存在且非空"（协议 §5.2）。
- 依据：2026-10-24 文档条文的机器判定约定（协混成套的说明文件条文）。

### 2.7 后端行为用真实事件样例保真 mock

- 规则：stream/tool 事件的测试样例必须来自 Pi 真实事件（含字段缺失/乱序/晚到的低槽位等配对），不造虚构字段。
- 依据：案例 C107（虚构整轮序号导致误判）＋`test/stream-events.test.mjs` 的"不关心的事件一律 undefined"断言。机器检查：`pnpm test`（stream-events）。

### 2.8 事件/状态链路必须测"重连、重放、乱序"

- 规则：凡走事件流（SSE/长连接）或跨重连保留状态的链路，测试必须至少覆盖：**断线重连（带历史事件重放）**、**旧回合终态晚到**、**乱序/重复事件**；只测 happy path 视为未验证。
- 依据：2026-10-24 C119（SSE 重连 `since=0` 重放旧 `done`，把仍在跑的第 3 步误标成 4/4 完成）。机器检查：`test/event-guards.test.mjs`（T16-T19）。

### 2.9 截图基线只比骨架，动态数据必须遮

- 规则：截图基线里不得包含会随用户正常使用变化的内容（token/usage 数字、相对时间、真实会话正文、项目/会话行）；这些区域必须标 `data-shot-mask`，基线只保留布局与控件。
- 依据：2026-10-24 状态条 usage 从 64k 涨到 239k，导致 5 张基线"未变化"检查假红 0.09–0.43%。机器检查：`pnpm test:ui`。

### 2.10 并发与快速切换必测

- 规则：会话/Agent 切换相关改动必须覆盖：**同 Agent 两会话并发都完成**、**切走后旧终态/旧对账不得改新会话**、**切回正在跑的会话必须恢复生成态**、**跨 Agent/项目的同号 Task 不得串标题**。
- 依据：2026-10-24 C120。机器检查：`test/event-guards.test.mjs`、`test/header-strip.test.mjs`、`test/model-follow.test.mjs`；并发的服务端验证见 Task 0005 记录。

### 2.11 端到端验证的提示词与夹具不得留下持久副作用；测试日期与实现同口径

- 规则：用真实模型做 E2E 时，提示词只能让助手"只回复文字、不写文件"（例：数数、只回一个字）；测试产生的会话/Agent 必须在 `finally` 里删除；测试中的日期必须与实现同口径（本地日期，见日志文件命名），不得用 UTC 替代；截图里的动态列表（用户文件系统、会话列表）用固定夹具。
- 依据：2026-10-25 C123（测试假红、动态目录截图假红、E2E 提示词写入用户日常分片）。机器检查：`test/logging.test.mjs`（同口径）、`frontend/test/ui-contract.mjs`（选择器夹具）。

### 2.12 断线重连必须经真实代理路径验证，并覆盖"假活着"

- 规则：事件流/长连接的重连测试，必须在与真实运行一致的路径上做（开发时经代理访问）；只测直连会漏掉代理吞掉断开的情况。必测：后端被杀后客户端在有限时间内重连并取得新快照；重连后后台事件仍能送达。
- 依据：2026-10-25 C124（直连测试通过、经 Vite 代理的页面永远收不到事件）。机器检查：`test/event-router.test.mjs`（T59 看门狗判定）；真实路径验证见 Task 0007 的记录。

### 2.13 状态派生必须穷举；端到端状态流转要做"数量 → 减少 → 归零"的闭环

- 规则：派生类纯函数（聚合、焦点排除、隐藏页签、孤儿）必须有穷举断言；端到端验证要覆盖"多个未读 → 查看一个（数量减一）→ 全部查看（徽标消失）"的完整闭环，并记录在 evidence。
- 依据：2026-10-25 C125。验证记录见 Task 0008 的 `evidence/`。

### 2.14 计数类改动必须用"数量 → 减少 → 归零"的数字例子验证，并逐层核对

- 规则：涉及徽标数字的改动，测试要用具体数字例子断言每一层（如 P1 三个未看、看一个 → P1 从 3 到 2、Agent 不变），而不是只断言"有/没有"。
- 依据：2026-10-25 C126。验证记录见 Task 0009 的 `evidence/`。

### 2.15 界面元素的契约必须断言到"几何"与"真实选择器"（必须）

- 场景：UI 契约要保证某个元素"看得见"（状态点、徽标、图标）。
- 规则：
  - **必须**用页面上真实存在的选择器取元素。写完**必须**先打印命中数——**命中 0 个的断言是恒绿的假断言**，它不是"通过"，是"没测"。
  - **必须**断言**有布局盒**：`getBoundingClientRect()` 的宽高达到设计尺寸（如 6×6 的点断言 `≥6×6`），且 `offsetParent !== null`（已挂载）。只看"元素在 DOM 里"不够——`display:inline` 包空 `span` 会渲染出 0×0，DOM 查询照样命中。
  - **应该**断言状态由注入的夹具决定（拦截 SSE 快照/接口响应），不依赖这台机器上恰好的数据；**必须**不写真实用户数据（标已读会改 `session-views.json`）。
  - **应该**按语义属性断言（`role="status"` + `aria-label` 带数量），不比 class 名——class 会随样式重构变，语义属性是契约。
  - **必须**让夹具跟实现的数据源走：实现的输入换了来源（例：三态从"前端 SSE 快照"改成"接口的 `activity`"），夹具**必须**同步改，否则断言会变成"新形态的假绿"（注入到没人读的地方 → 点永远 0 个 → "没有 0×0 的点"反过来成立）。**必须**在"存在性"断言里显式写"0 个 = 没测"，不要让它悄悄通过。
- 为什么：本项目同一类缺陷发生过两次。第一次（C161）状态点被 `display:inline` 压成 0×0，门禁用 `[data-session-id]`（前端从未渲染该属性）和 `[title="完成未读"]`（真实值带后缀）取值，两者都命中 0，断言只剩"数页面上的元素个数"→ 恒绿。第二次是修复只在分支、没合并进主线，用户看到的仍是坏的。
- 活性验证（配合 2.4）：把实现改回错误写法，这条断言**必须**立刻变红；红不了说明它还是假断言。

### 2.16 有跨端副作用的功能，必须测到"通知带什么 + 对端做什么"（必须）

- 场景：一个操作会改状态，并**通知别处**（删除会话 → 发 `removed` 补丁；改标题 → 发补丁）。
- 规则：这类链路有**三段**，测试必须覆盖全部：
  1. **源头状态变了**（服务端索引/计数）；
  2. **通知里带全了对端所需的信息**（本项目：`removed` 必须带 `was` 与 `projectId`；
     且"该减哪一格"的判定与源头聚合**共用同一个函数**）；
  3. **收到方据此做对了事**（端到端：DELETE 之后快照/UI 的数字减少）。
  只测第 1 段 = 没测。**必须**再用一次实机验证（读真界面的数字），因为那是用户唯一能感知的层。
- 边界**必须**覆盖：删到 0（分组消失）、删一条**已看过**的（数字不该变、不能减成负数）、
  删一条正在跑的（被 409 拒绝，通知不该发出）。
- 依据：C172 —— 只测了服务端计数减少，漏了客户端更新；用户实测「删了一个未读，数量没有减少」。

### 2.17 报告"这是 bug"之前，先证明测量通道是对的（必须）

- 场景：端到端/UI 验证得出"功能没生效"的结论，准备去改代码。
- 规则：**必须**先确认四件事，答不上来就不能说"代码有 bug"：
  1. **端口上是不是我的进程**：`lsof -nP -iTCP:<port>` + `ps -p <pid> -o command=`（应有我的 `--port`）；
  2. **下发的是不是最新代码**：`curl localhost:<port>/src/X.tsx | grep <新加的特征串>`；
  3. **页面加载完了没有**：先等到某个**已知元素**出现，再判断数据相关的东西
     （本项目实测需要 12–16 秒，等 6 秒就下结论会得到"全空"）；
  4. **IPv4 还是 IPv6**：`localhost` 与 `127.0.0.1` 各试一次。
- 造测试数据时**必须**用"现在 ± 偏移"的时间戳，**必须不**写死未来的绝对时间
  （会让 `viewedAt < completedAt`，看起来像"已读没生效"）。
- 依据：C169、C173 —— 六次误判里有五次是测量工具错了，代码一直是对的。

### 2.18 状态类缺陷：先跑四层核对，再改代码（必须）

- 场景：用户报"数字/点对不上"（显示未读但没有点、正在跑但没有数字、点开不消失、数字和点不同步）。
- 规则：**必须**先跑 `pnpm state`（`scripts/session-state.mjs`），按它给的第一处不一致定位，不允许凭读代码猜。四层是
  L1 磁盘索引 / L2 SSE 快照（**服务端此刻的真相**）/ L3 行对象 API / L4 真浏览器 DOM：

  | 不一致发生处 | 结论 |
  |---|---|
  | L2 ≠ L3 | 后端两条路径口径不一致（`unread()` vs `rowActivityOf()`） |
  | L3 ≠ L4 | 前端渲染问题（`applyRowPatch` / `sessionSlots` / `deriveStatus`） |
  | L1 ≠ L2（非 running） | 落盘/内存不一致（重启会丢未读） |
  | 四层全一致 | **视觉问题**（颜色/尺寸/动画不够分明），不是逻辑 bug —— 不要改逻辑 |

- **必须**记住 `running` 是纯内存态、**不落盘是正确设计**，所以"L1 没有 running"不构成不一致。
- 修完之后**必须**再跑一次，确认四层一致（而不是只确认单测变绿）。
- 依据：2026-11-05 用户连续三次报状态问题，每次都靠零散 fetch 猜，二十多分钟无结论；
  用户原话「如果前端展示的数字来源没问题，那前端一定能正常展示」。工具说明见 `tools/session-state/AGENTS.md`。

### 2.19 动画不能改变被测元素的几何尺寸（必须）

- 场景：给"运行中"元素加呼吸/脉冲动画，且它被 `≥N×N` 的几何门禁断言覆盖。
- 规则：**必须**用**放大**（`scale ≥ 1`）或**不改变几何**的属性（`box-shadow`、`opacity`、`filter`）做呼吸，
  **禁止**用缩小（`scale < 1`）—— `getBoundingClientRect()` 返回的是**变换后**的盒子，
  缩小会让同一页面在动画不同时刻时而通过、时而失败（本项目实测：6px 的点缩到 .70 时只有 4.2px，
  `≥6×6` 的门禁直接变红；16px 徽标缩到 11.2px 同样失败）。
- 同时：**必须**保证动画的**最小值** = 基准尺寸（`scale` 从 1 开始向上），这样任何时刻都满足几何下限。
- 为什么不用 `prefers-reduced-motion` 绕过：那只是关掉动画，正常用户的机器上仍会假红。
- 依据：Task 0005 徽标三次调速 —— .88 → .80 → 「放大 1.12 / 1.35 + 扩散环」，
  前两次都因几何断言在动画低谷期变红。

### 2.20 打桩测前端状态机：SSE 用注入的假 EventSource，不用 route.fulfill 流（必须）

- 场景：要覆盖"收到某个 SSE 帧后界面怎么变"，且不能依赖真后端与真模型。
- 规则：
  - **必须**用 `page.addInitScript` 注入假 `EventSource`，由测试**手动、按时序**推帧
    （`window.__push(name, data)`），不要用 `route.fulfill` + `TransformStream`
    —— 实测 Playwright 下 writer 拿不到、增量帧到不了页面。
  - 拦截 REST **必须**用**一个函数式 route 按 URL 分发**，不要用多条通配 route：
    实测 `**/api/agents` 会吃掉 `/api/agents/x/projects`，导致分组永远为空（"全 0"的假结论）。
  - 读数据前**必须**先等已知元素出现且**行数 ≥ 期望条数**，不能只等第一个选择器（会漏行）。
  - 覆盖场景**必须**包含"同一状态重复推 5 次"与"重连重放同一快照"——那是防计数器回归的用例。
- 依据：Task 0005 场景矩阵（12 组场景 / 29 条断言）—— 它抓出了两个真 bug
  （快照不更新行的点、`{unread:null}` 误删 running 槽），这两条都没有被任何单测覆盖。
