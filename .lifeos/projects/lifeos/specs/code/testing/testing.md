# 测试用例规范

> 角色：架构 / 开发　类型：规范（测试）　状态：现行（2026-10-24）
>
> 场景与入口见仓库根 `AGENTS.md`；检视流程与结论分级见 `specs/review/review.md`；本文只写测试怎么写。

## 怎么用

写新用例/读老用例时对照 §2；每类门禁要能证明自己活着（遇到尸变断言要被封掉）；违反 = 缺陷。

## 2 条文

### 2.1 隔离：写只入临时家目录，真实数据只读；mock 先断言命中

- 规则：家目录用 `installHome`+`LIFEOS_HOME` 临时目录；真实用户会话/配置绝不写；route mock 需要一条"已命中"断言（防止模式写错打到真实接口）。
- 依据：案例 C051、C039、C047（验证环境不干净 → 误改真实模型）。机器检查：现有 `test/*.test.mjs` 全部临时 home 模式。

### 2.2 每个新接口至少一条非 2xx，断言 code/原因而非状态码

- 规则：不存在/非法入参/鉴权失败/打架（运行中）成套写；错误语义测试不因状态码微调而变绿。
- 依据：案例 C050（No API key 被报 404"找不到"）。机器检查：`test/api.test.mjs` 的失败分类用例。

### 2.3 配置类页面四态必测：加载/错误/脏/无数据

- 规则：依赖后端状态的界面写齐四态断言（加载未完禁写、失败有出口、脏关闭提示、空数据禁保存）。
- 依据：案例 C086（AgentConfig 保存空值/永远加载中/丢改动/空模型可保存）+ C106。机器检查：`frontend/test/ui-contract.mjs` + config 页面用例。

### 2.4 每类既有缺陷补"制造缺陷 → 门禁变红"的活性验证

- 规则：门禁门槛数目/关键项存在性可断言；改一个 token 或删一段基线时必须红；门禁脚本与实现同 commit，改脚本要写明原因。
- 依据：2026-10-18 基线段落被误删仍全绿的事故（案例详情待历史迁移补编号）。机器检查：`frontend/test/ui-contract.mjs` 自检段。

### 2.5 断言行为结果，不断言实现细节

- 规则：测试描述用户可验证的行为（"列收起后聊天不被压破"），不命中函数名/成员名等内部结构。
- 依据：仓库根 `AGENTS.md`（"针对性测试覆盖真实场景与边界"）+ 2026-10-18 体检（断言漂移教训）。机器检查：`pnpm test`。

### 2.6 结构改动三道闸一起跑：doc-links + home:check + home.test

- 规则：改 `.lifeos` 模板/结构除常规测试外必跑 `pnpm home:check`、结构链接门禁 `test/doc-links.test.mjs`；验证"说明文件存在且非空"（协议 §5.2）。
- 依据：2026-10-24 文档条文的机器判定约定（协混成套的说明文件条文）。

### 2.7 后端行为用真实事件样例保真 mock

- 规则：stream/tool 事件的测试样例必须来自 Pi 真实事件（含字段缺失/乱序/晚到的低槽位等配对），不造虚构字段。
- 依据：案例 C107（虚构整轮序号导致误判）＋`test/stream-events.test.mjs` 的"不关心的事件一律 undefined"断言。机器检查：`pnpm test`（stream-events）。

### 2.8 事件/状态链路必须测"重连、重放、乱序"

- 规则：凡走事件流（SSE/长连接）或跨重连保留状态的链路，测试必须至少覆盖：**断线重连（带历史事件重放）**、**旧回合终态晚到**、**乱序/重复事件**；只测 happy path 视为未验证。
- 依据：2026-10-24 C119（SSE 重连 `since=0` 重放旧 `done`，把仍在跑的第 3 步误标成 4/4 完成）。机器检查：`test/event-guards.test.mjs`（T16-T19）。

### 2.9 截图基线只比骨架，动态数据必须遮

- 规则：截图基线里不得包含会随用户正常使用变化的内容（token/usage 数字、相对时间、真实会话正文、项目/会话行）；这些区域必须标 `data-shot-mask`，基线只保留布局与控件。
- 依据：2026-10-24 状态条 usage 从 64k 涨到 239k，导致 5 张基线"未变化"检查假红 0.09–0.43%。机器检查：`pnpm test:ui`。

### 2.10 并发与快速切换必测

- 规则：会话/Agent 切换相关改动必须覆盖：**同 Agent 两会话并发都完成**、**切走后旧终态/旧对账不得改新会话**、**切回正在跑的会话必须恢复生成态**、**跨 Agent/项目的同号 Task 不得串标题**。
- 依据：2026-10-24 C120。机器检查：`test/event-guards.test.mjs`、`test/header-strip.test.mjs`、`test/model-follow.test.mjs`；并发的服务端验证见 Task 0005 记录。

### 2.11 端到端验证的提示词与夹具不得留下持久副作用；测试日期与实现同口径

- 规则：用真实模型做 E2E 时，提示词只能让助手"只回复文字、不写文件"（例：数数、只回一个字）；测试产生的会话/Agent 必须在 `finally` 里删除；测试中的日期必须与实现同口径（本地日期，见日志文件命名），不得用 UTC 替代；截图里的动态列表（用户文件系统、会话列表）用固定夹具。
- 依据：2026-10-25 C123（测试假红、动态目录截图假红、E2E 提示词写入用户日常分片）。机器检查：`test/logging.test.mjs`（同口径）、`frontend/test/ui-contract.mjs`（选择器夹具）。

### 2.12 断线重连必须经真实代理路径验证，并覆盖"假活着"

- 规则：事件流/长连接的重连测试，必须在与真实运行一致的路径上做（开发时经代理访问）；只测直连会漏掉代理吞掉断开的情况。必测：后端被杀后客户端在有限时间内重连并取得新快照；重连后后台事件仍能送达。
- 依据：2026-10-25 C124（直连测试通过、经 Vite 代理的页面永远收不到事件）。机器检查：`test/event-router.test.mjs`（T59 看门狗判定）；真实路径验证见 Task 0007 的记录。

### 2.13 状态派生必须穷举；端到端状态流转要做"数量 → 减少 → 归零"的闭环

- 规则：派生类纯函数（聚合、焦点排除、隐藏页签、孤儿）必须有穷举断言；端到端验证要覆盖"多个未读 → 查看一个（数量减一）→ 全部查看（徽标消失）"的完整闭环，并记录在 evidence。
- 依据：2026-10-25 C125。验证记录见 Task 0008 的 `evidence/`。

### 2.14 计数类改动必须用"数量 → 减少 → 归零"的数字例子验证，并逐层核对

- 规则：涉及徽标数字的改动，测试要用具体数字例子断言每一层（如 P1 三个未看、看一个 → P1 从 3 到 2、Agent 不变），而不是只断言"有/没有"。
- 依据：2026-10-25 C126。验证记录见 Task 0009 的 `evidence/`。
