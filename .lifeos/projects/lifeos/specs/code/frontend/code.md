## 怎么用

## 2 条文

### 2.1 生成状态由显式事件/标记驱动，禁止用"值不相等"猜语义

- 规则：需要一个"用户改过/系统变了"的判断时，用显式动作产生的标记（entry / 事件），不靠值比较。
- 依据：案例 C071（默认模型跟随——靠值相等猜测导致默认永远跟不上）。机器检查：`pnpm test`（model-follow）。
- 依据：模型默认裁决与来源标注见 `knowledge/architecture/agent.md`。

### 2.2 写操作必须覆盖"无会话"分支，选中态由写实现校正

- 规则：改全局/Agent 级状态时，无会话场景单独取数（默认配置接口），不能只刷新会话 meta；列表刷新时校正选中态（回退默认/最新，清掉指向已删对象的选择）。
- 依据：案例 C085（AgentConfig 改默认模型 + agents_changed 校正）。机器检查：`pnpm test`（agents_broadcast 用例）。

### 2.3 同类 UI 第二次出现 → 立"容器 + 注册项"，不为单个动作加常显特例

- 规则：同一类动作/部件（消息动作条、工具块、状态条项）第二次出现时抽容器，功能只声明元数据（名称/图标/文案/权限）；可见性规则全类统一，反馈期间强制可见，不给"救命按钮"开常显例外。
- 依据：案例 C059、C061、C066（动作条三次返工）、C056/C062（常显特例被用户要求改回）。

### 2.4 悬停控件用 `opacity + pointer-events`，不用 `display:none`

- 规则：悬停显现用透明度开关避免布局跳动；键盘焦点/反馈期间强制可见；触屏（无悬停）常显由统一可见性约定实现。
- 依据：案例 C056（复制按钮 display 跳动）+ frontend-spec §5/§9（可见性契约断言，`pnpm test:ui`）。

### 2.5 生成中的键序是契约：Esc=打断、Enter=steer、↑/↓ 历史方向用测试锁

- 规则：输入历史与队列的方向性不做"读码推断"，写契约测试（↑ 取回、清空后 ↓ 返回、生成中 Enter=插话不发送）。
- **必须**：断言要覆盖「多条历史 + 两个会话 + 连按」三种形态。只测"发一条、按一次 ↑"的断言在四个缺陷同时存在时依然全绿（2026-11-05 实测：方向反、只能走一步、跨会话串、索引不复位一个都没拦住）。
- **必须**：会话级输入状态（历史、草稿）只允许**派生自会话事实**，不允许另记一份需要"记得清"的流水；确实要记游标时，游标必须带作用域，作用域一变即失效。
- 依据：案例 C105（输入历史方向反了）、C107、C163（四个缺陷一次叠在输入历史上）。机器检查：`pnpm test`（`test/input-history.test.mjs` 13 条纯函数契约）+ `pnpm test:ui`（`ui-contract.mjs` 的 7 条双会话界面断言）。

### 2.6 主保存必须覆盖整张表单；多加载 effect 用函数式合并；脏基线=打开时原始值

- 规则：用户看到整页表单时 primary 保存不得只保存一半；关闭确认要写明脏域；初始基线用打开快照，多个加载 effect 用 functional update 合并。
- 依据：案例 C106（改模型后 footer 存一半仍提示未保存）。机器检查：配置页四态测试（testing 规 2.3）。

### 2.7 流式按 assistant message 分段；`contentIndex` 是消息内序号；工具 running 由执行事件驱动

- 规则：消费 Pi 事件时以 `message_start/end` 为段边界，不做整轮全局槽位；thinking/tool 的 live 各自收口；最终答案取最后一段 text；块序只按到达与段内序号。
- 依据：案例 C107、C111（两次返工后定稿）。机器检查：`pnpm test`（stream-blocks / stream-events 全量映射）。

### 2.8 数值/颜色只进 tokens.css，宽度只进 layout() 纯函数

- 规则：组件不写字面量数值/颜色/宽度；命中区、对比度等可视常量做成可断言数值；每处宽度计算走同一条纯函数与不变量断言。
- 依据：2026-10-18 前端体检（MIN_CHAT 三处各自漂移；丑→可断言数值）。机器检查：`pnpm lint:tokens` + `pnpm test`（ui-layout）。

### 2.9 心跳/超时计时器在动作开始时重置；判丢前先向后端确认

- 规则：任何"多久没动静"的逻辑以"上一事件时间"为基线；发送/打断后立刻重置；判丢前查 `GET …/sessions/:sid` 的 `meta.running`，还在跑给第二窗口。
- 依据：案例 C067（页面静置后发送 10ms 内误报中断）。机器检查：`pnpm test`（心跳用例）。

### 2.10 呈现层不直接消费原始事件流（架构硬约束）

- 界面组件只消费 `run-facts`（纯函数：事件+时钟 → 每会话 running/unread/queued/lastTurn）与消息渲染块（stream-blocks）这两个派生层；任何组件直接 `new EventSource` / 读原始事件属缺陷；
- 列表运行点、完成未读、未来通知/换皮都只能作为 run-facts 的观察者；UI 换皮不动机制（呈现与机制解耦的落实条文）。

### 2.11 前端日志与心跳窗口可注入

- 前端 console 结构化输出 + 批量上报 `POST /api/logs`（pagehide flush；error 必报、info 采样）——同后端 2.10 字段与文件约定；
- 心跳窗口（60s）与轮询间隔（5s）定义为模块常量并允许测试覆盖，契约测试不等待真实时间。

### 2.12 跨作用域缓存与全局运行态必须带归属，切换即清

- 规则：缓存的键必须包含完整作用域（agent / project / 实体 id）；`busy`、`activeTurnId` 这类运行态必须绑定 `sessionId`；切会话/切 Agent 时先清空，异步对账/请求返回后再校验"仍在同一作用域"。
- 依据：2026-10-24 C120（跨 Agent 串任务标题、切会话误报中断）。机器检查：`test/event-guards.test.mjs`（T21）、`test/header-strip.test.mjs`。

### 2.13 事件分流规则放纯函数，组件只执行动作；派生值先声明再使用

- 规则：多 Agent 事件的分流（基线、焦点、回合级 vs 细节级、完成提示）写在纯函数（`event-router.ts`）里并穷举测试；组件只执行返回的动作，不在组件里判断。长生命周期的连接（EventSource）只建一次，处理函数每次渲染换新，通过 ref 转发，避免闭包读到旧状态。派生值（如 `attention`）必须在被渲染的代码之前声明（否则是运行时的暂时性死区错误，2026-10-25 实测）。
- 依据：2026-10-25 C122（Agent 行访问 `attention` 早于声明，页面整体报错，E2E 才暴露）。机器检查：`test/event-router.test.mjs`（T47–T52）；E2E 验证见 Task 0007 的验证记录。

### 2.14 状态语义只有一套，聚合只派生，颜色走拍板语义

- 规则：会话/项目/Agent 的运行与未读状态只由 `status-map.ts` 的纯函数派生；组件不得自己拼聚合。未读数量按会话计；未读的颜色是拍板的绿色（不是蓝色）；数量徽标的颜色只用令牌（`success-soft` / `success`）。
- 依据：2026-10-25 C125（未读颜色与拍板不一致 → 用户看见蓝点误以为是生成中；两层状态各自为政，Agent 只有二选一没有数量）。机器检查：`test/status-map.test.mjs`（T61–T64）、`pnpm lint:tokens`。

### 2.15 一个位置的数字只有一种含义；计数规则逐层定义，不能用一层代替另一层

- 规则：行上的绿色徽标数字只表示"待查看"（Project = 未看会话数，Agent = 待看 Project 数）；总数只出现在列头统计里。Agent 的数字不得等于其下会话数之和。
- 依据：2026-10-25 C126（上一版 Agent 数字写成会话数之和，且项目行同时显示总数与未读数，用户无法分辨）。机器检查：`test/status-map.test.mjs`（T67–T69）；视觉对比度 `frontend/test/ui-contract.mjs`（统计小药丸的文字色达标）。

### 2.16 全局单例状态（高亮注册表、cache、id 计数器）的清理必须按归属，且要有跨归属回归测试

- 规则：凡是对全局单例做 `delete` / `clear` / 覆盖写的地方，必须先确定"这条状态是不是我的"：高亮注册表 `CSS.highlights` 的名字带 owner（`anno-<markId>--<messageId>:<blockIndex>`），缓存键带完整作用域，id 生成必须对"当下已知集合"查重。测试夹具至少要两个归属先后跑，断言"先来的那个还活着"。
- 依据：2026-11-05 C025（`paintAnnotations` 按块清全局 registry，兄弟块的批注高亮被擦，表现为"鼠标靠近才高亮"）、C024 同源缺陷（模块级 id 计数器 + 服务端持久数据 → 刷新后新建批注与旧 id 撞车，落盘静默覆盖）。机器检查：`test/annotations-paint.test.mjs`（owner 隔离 3 条）、`test/annotation-id.test.mjs`。

### 2.17 静态资源的缓存与回退：缺失的文件必须 404，入口 HTML 必须 no-cache

- 规则：静态服务不得把"看起来像文件"的缺失路径回退成 `index.html`；`/assets/*`（带内容 hash）用 `immutable` 长缓存，`index.html` / `sw.js` / `manifest` 必须 `no-cache`。任何一处缺失，一次重新构建就会让缓存了旧 HTML 的老页面永久白屏。
- 依据：2026-11-05 C023（`GET /assets/index-<旧hash>.js` 返回 `200 text/html` → module script MIME 报错 → `#root` 永远空，刷新也无效）。机器检查：`test/static.test.mjs`。

### 2.18 effect 里的请求守卫写"请求过了"，不写"缓存里有值"

- 规则：数据加载 effect 的守卫条件必须能在"响应正常但不含所需数据"时变成假。按 key 记"已请求过"的集合，请求 200 即记（失败不记，留待重试）；不得用"缓存里已有该 key 的值"当唯一守卫。
- 依据：2026-11-05 C023 第二缺陷（清单里没有某个 taskId 时守卫永远为假，实测 3 秒 **2664 次** `/tasks` 请求，当天日志 96% 是这一个端点）。机器检查：`test/task-title-cache.test.mjs`。

### 2.19 连续手势不驱动 React 状态：手势期间写 DOM，结束时提交一次（必须）

- 场景：拖动分栏、拖动画布、滑动条、按住拖动排序 —— 任何"鼠标/手指连续移动"的交互。
- 规则：
  - **必须** 手势进行中只写 DOM（`el.style.x = ...`），并用 `requestAnimationFrame` 合并到一帧最多一次；
  - **必须** 松手（`mouseup` / `pointerup` / `touchend`）才提交一次 React 状态，并清掉内联样式交还给渲染层；
  - **必须不** 在手势回调里 `setState` —— 那会让整棵子树按鼠标事件频率重渲染。
- 为什么：本项目实测（2026-11-09）拖动列宽每次 `mousemove` 都 `setState`，108 条消息的会话里
  一次拖动产生 **4 个 108–148ms 长任务**、帧 p90 16.7ms、最长 160ms；**同一操作在空会话里零长任务**
  —— 成本全在"重渲染整条消息列表"，与拖拽逻辑无关。改成写 DOM 后：拖动期间 **0 长任务**，
  帧 p90 9.2ms、最长 25ms（生产构建）。
- 边界：如果手势必须实时反馈一个**远离该 DOM 的派生值**（如另一个区域的数字），
  用 `requestAnimationFrame` + 一个 ref 直写那个元素，或用 CSS 变量让浏览器自己算；
  **不得**为了它把整个状态提到 React。
- 机器检查：`frontend/test/ui-contract.mjs`（「拖动列宽：拖动过程中无长任务」）。
- 判断方法：同一手势在「空数据」与「大数据」下各测一次 —— 时长随数据量涨 = 重渲染成本；
  与数据量无关 = 逻辑成本。

### 2.20 交互能力必须"写上标记就生效"，不许"记得去清单里加一行"（必须）

- 场景：一类可复用的交互能力（可拖宽列、可折叠块、可复制的值、可打开的对象）。
- 规则：
  - **必须** 把能力收敛成一个组件/一条约定（如 `<ResizeColumn resizeKey="cX">` + `data-resize-key`），
    新区域**写上它就自动具备**全部行为（状态、命中区、键盘、动效、持久化）；
  - **必须不** 用"手写映射表 / 中央注册数组"表达"哪些地方有这个能力" ——
    漏登记的一方会静默降级（表现为"别人是好的，就这里不行"，且没有任何报错）；
  - **必须** 让门禁**遍历页面上的标记**（`[data-resize-key]`）来验证，而不是枚举已知用例；
    这样新增区域自动被覆盖，漏写标记或标记失效都会变红。
- 依据：2026-11-09 拖动统一前，五个可拖区域只有两个跟手 —— `c5`/`c4` 拖动全程不动、
  `c4t` 连按都按不到（把手被父级 `overflow-hidden` 裁掉）。根因是能力绑在
  `{c1:"agents", c2:"sessions"}` 这张手写表上，**没被点名的地方就是坏的**。
- 机器检查：`frontend/test/ui-contract.mjs`（三个场景 × 「每个可拖区域都能抓住把手」
  + 「每个可拖区域拖动都逐帧跟手」）。

### 2.21 样式的修复条件若与"容器宽度"相关，不得用视口断点（必须）

- 场景：给内容块写响应式（表格、代码块、卡片网格、工具栏）。
- 规则：
  - **必须** 先问"触发条件是屏幕宽度还是容器宽度"；可拖列宽、可收展面板、抽屉里的内容，
    触发条件是**容器宽度**，必须用容器自适应（`max-width: 100%` + `overflow-x: auto` +
    内容下限如 `min-width: 4.5em`），**必须不**用 `@media (max-width: …)`；
  - **必须** 为这类样式写两条契约：一条在宽容器下，一条在**真实操作制造出的窄容器**下
    （例如"打开完整历史"把正文列从 1024 压到 584），不得靠改 CSS 变量伪造。
- 依据：2026-11-09 同一张 Markdown 表格两次被压成逐字竖排 —— 第一次在手机（390），
  用 `@media (max-width: 639px)` 修掉；第二次在桌面打开完整历史后（正文 584），断点不生效，
  「耗时」又被压成「1-2 / 小 / 时」三行。
- 机器检查：`frontend/test/ui-contract.mjs`（「正文表格：最窄一列不被压到逐字竖排（宽列下）」、
  「正文表格：正文列变窄后依然不压字」）。

### 2.22 浮层（popover/modal/toast）只允许用 design/surface.ts 的配方与层级（必须）

- 场景：任何"浮在内容之上"的表面 —— 下拉面板、预览气泡、模态、Toast、抽屉。
- 规则：
  - **必须** 从 `design/surface.ts` 的 `SURFACE[tone]` 取圆角/边界/阴影/内距，`LAYER_CLASS[name]` 取层级；
  - **必须** 边界统一用 `ring-1`（`border` 占 1px 布局，两个浮层并排时边框会差 1px）；
  - **必须** 阴影用 `--surface-*`（深浅色各一套，深色带 1px 白色描边），**必须不** 用 Tailwind 的
    `shadow-md/lg/xl`（固定黑投影，深色底下几乎不可见 —— 实测 `#292828` 上肉眼无差）；
  - **必须** 层级只用 `rail / popover / drawer / modal / toast` 五个语义名，**必须不** 写裸 `z-<数字>`
    （现状教训：Toast 与 Modal 同为 50 → 模态打开时看不到 toast）；
  - **应该** 用 `Popover` primitive（`design/popover-view.tsx`）而不是自己拼定位 + 关闭逻辑
    （定位算法在 `design/popover.ts`，纯函数可穷举；组件补了外点关闭/Esc/焦点归还）。
- 依据：2026-11-09 审计 —— 5 个浮层 5 套写法（border+shadow-md / ring+shadow-lg / ring+shadow-xl …），
  而 `tokens.css` 的 `--surface-popover/-modal` 早已算好却 0 使用。
- 机器检查：`test/design-system.test.mjs`（禁裸 shadow-*、禁裸 z-、LAYER 与 index.css 一致、遮罩只有一种）。

### 2.23 token 写了就必须有人用；不能用"看起来合理"的数值当上限（必须）

- 场景：往 tokens.css / theme.ts 加新的设计 token；给任何可拖/可调的东西定上限。
- 规则：
  - **必须** 让每个新 token 至少有一个消费者（组件或 primitive）；只想"留给未来"的必须先说明理由
    并写进测试的 `ALLOW_UNUSED`（默认不允许）；
  - **必须** 让上限与"它所在容器的真实尺寸"同源：嵌套区域的上限由外层算出，
    而**外层算尺寸的公式只能有一处**（本项目：`layout()`；`maxWidthOf()` 必须向它要值）；
  - **必须不** 在预算公式里加减"命中区厚度/装饰宽度"这类**不影响布局**的量
    （教训：`maxWidthOf` 多减 `HANDLE_HIT(8)`，导致"拖到 436 就停而面板实际能到 444"，
    同类缺陷发生过两次：c1 的 440 常量、c4t 的重复预算）；
  - **应该** 用"关系断言"而不是"数值断言"锁住设计意图（如 hover < 选中 < 选中 ≈ hover×2），
    数值可以调、关系不能反。
- 依据：2026-11-09 审计 —— `--surface-popover/-modal`、`--motion-*`、`--tracking-*`、`--radius-full`
  写好了但 0 使用；五套浮层由此而生。上限漂移两次都造成"拖不动"。
- 机器检查：`test/design-system.test.mjs`（token 使用率、状态强度关系、分层方向、层级一致性）。

### 2.24 视觉回归用固定夹具 + 矩阵；基线入库（必须）

- 场景：截图基线 / 视觉回归。
- 规则：
  - **必须** 用 route mock 的**固定夹具**渲染（agents / sessions / messages / profile / ui-prefs），
    **必须不** 让真实家目录的用户数据进基线（本轮两次假红都源于此）；
  - **必须** 覆盖「页面 × 深浅色 × 视口」矩阵（`pnpm test:visual`：5 × 2 × 2 = 20 张）；
  - **必须** 基线入库（`frontend/test/visual-matrix/`），输入产物（`.visual-matrix-shots/`）忽略 ——
    基线不入库时"换机器首次跑"等于没测；
  - **必须** 差异时先看报告（左基线/右本次），先判断"差异是我想改的吗 / 旧基线本身是不是错的 /
    新图里有没有用户数据"，三者答完再决定刷新还是改实现。
- 依据：2026-11-09 —— `folded.png` 长期"稳定通过"是因为它一直在比两张空白页；
  头像"白底白字"在零散图里没人看，在矩阵里一眼可见。
- 机器检查：`scripts/visual-matrix.mjs`（20 张全一致才算通过）。

### 2.25 可点击容器内部不得再放可点击元素（必须）

- 场景：列表行、卡片、整块可点的区域，右上角/行尾还要放图标按钮（配置、删除、历史）。
- 规则：
  - **必须** 把"主点击区"与"行内动作"渲染成**兄弟**：外层容器只负责底色与 hover 分组，
    主点击区是 `role="button"`（或 `<button>`），动作是有序的 `<button>` 列表；
  - **必须不** 让 `role="button"` / `<button>` 套住另一个 `button` / `a[href]` / `role="button"`
    —— axe 的 `nested-interactive` 明确禁止，读屏与键盘会出现"两个目标叠在一起"；
  - **必须** 单个 primitive 提供 `actions` 之类的槽位（本项目 `Row` 的 `actions`），
    页面不要自己往 children 里塞按钮 —— 否则下一个调用点又会套回去；
  - **应该** 把"隐藏入口"（点头像配置）移到动作区，让动作集中在一处（找得到、也可断言）。
- 依据：2026-11-09 axe 审计 34 处 `nested-interactive`（助手行头像按钮、会话行三按钮）。
- 机器检查：`pnpm audit:a11y`（serious/critical 含 `nested-interactive` 必须为 0）。

### 2.26 语义 soft 底（danger-soft / success-soft / running-soft）必须给深色值（必须）

- 场景：任何"浅底 + 同色深字"的语义块（失败提示、成功徽标、进行中标签）。
- 规则：
  - **必须** 让 `*-soft` 在深色模式下重算（本项目 `index.css` 的 `[data-theme-mode="dark"]`），
    **必须不** 直接把浅色的固定值搬到深色（深色下"浅粉底 + 浅红字"只有约 1.5:1）；
  - **必须** 用语义 token（`bg-danger-soft`）而不是曾经的一次性色板（`--color-message-failure`），
    否则深色重算覆盖不到；
  - **应该** 成功的同类块（`tool-done`）与失败的同类块（`tool-error`）共用同一族 soft，
    语义相同的两块**同色是正确的**，不要为了"看得出区别"再造一档。
- 依据：2026-11-09 axe 审计（失败块在深色下 11 处 color-contrast，含 `bg-message-failure`）。
- 机器检查：`pnpm audit:a11y` + `test/design-system.test.mjs`（对比度矩阵）。

### 2.27 拖宽的语义是「拖哪条边，哪条边跟手」（必须）

- 场景：任何可拖宽的列、分隔条（c1/c2/c4/c4t/c5 与未来一切分栏）。
- 规则：
  - **必须** 让用户抓着的那条分隔条在**每一帧**都贴着鼠标（_coordinate_ 断言：分隔条 x 位移 ≈ 鼠标位移，
    偏差 ≤ 4px/帧）。宽度数值对了不算跟手——把手不动、另一条边反向移动的实现，宽度断言恒绿但方向感全错；
  - **必须不** 用「一条边的移动量 = 另一条边的反向补偿」实现变宽（旧嵌套版的「树长多少面板往左长多少」）；
  - **必须** 内层变宽只吃**同级**空间（文件树吃查看器），**必须不** 自动改写无关节点（左列、聊天列）的宽度——
    旧版顶到上限后还从左列「借宽」且借走不还；
  - **应该** 内外层职责分离：内层把手只管内层分界，外层把手（整个面板宽度）才动外层总宽；
  - **应该** 把手到边界就停（可预期的死区），不用让界反向扩张来制造"还能拖"的错觉。
- 依据：2026-11-10 用户（原话「我往右拖呢，它在往左边扩张」）：实测 1600 拖树 +100，
  把手 x 恒 1237、面板左缘 1000→900、c2 300→240 借走不还。修复同步发现并修掉了
  「松手清 inline 宽度 → 状态无变化不重渲染 → 列被 content 顶宽」（444→527）。
- 机器检查：`frontend/test/ui-contract.mjs`（嵌套拖动块：分隔条 x 跳既精度断言 +
  面板/左列宽度不变）+ `test/ui-layout.test.mjs`（嵌套拖动块：面板/左列不变量、
  查看器几何等价、往返无漂移）。

参考：参考实现语义对齐：opencode `session-panel-width.ts`（只保对侧最小宽）、
open-webui `ResizableSidePanel.svelte`（`dx` 直接换算宽）；详细对比与删借宽的取舍见
`knowledge/design/layout-model.md` §6。

### 2.28 行尾动作必须走容器的槽位（hover 出现，不占常驻空间）（必须）

- 场景：列表行尾的图标动作（助手行的「配置/删除」、会话行的「历史/重命名/删除」，以及未来的树/文件行）。
- 规则：
  - **必须** 用 `design/ui.tsx` `Row` 的 `status` + `actions`（状态与动作叠在同一栅格格，隐藏不塌、显示不抖）；
  - **必须不** 在使用点自己写 hover 分支（`opacity-0 group-hover:*` 之类只许存在于 Row / SessionRow 容器内部）——
    2026-11-10 起 SessionRow 的手写版保留运行；**新增**带动作的行**必须**走 Row，不得复制第二份；
  - 动作隐藏时状态徽标必须可见（`StatusMarks` 挂 `status` 槽），hover 两者换位 —— 不要出现"格里悬空一段空白"；
  - 键盘可达（`group-has-[:focus-visible]` 强制显现）与触屏分支（`@media(hover:none)`）由容器统一提供。
- 依据：2026-11-10 用户（助手行两按钮常驻把列表拉长，"和会话列表里那个一样，鼠标移上去才显示"）。
  上移前的形态见 `evidence/ui-round8/`（idle 一行干干净净、hover 右端两钮）。
- 机器检查：`frontend/test/ui-contract.mjs`（助手行五条：默认隐藏 / hover 出现 / 移开隐藏 / 不可误点 / Tab 可见）。

### 2.29 文字选区必须分档：正文实心、代码区 alpha（必须）

- 场景：`::selection`（消息正文、文件树、Markdown、源码、diff 的拖选高亮）。
- 规则：
  - **必须** 全局 `::selection` = `--color-accent-solid` 底 + 白字（token 在深浅色下都保证白字 AA ——
    它的语义就是"白字底"）；
  - **必须** `pre ::selection` = alpha 档（light `30%` / dark `50%`，`color-mix` 透明化）+ `color: currentcolor`，
    **必须不** 用实心底盖住代码块的语法色；
  - **必须不** 用 `*-soft` 一类"底色需要随模式重算"的 token 当选区底 —— 2026-11-10 的实测缺陷：
    `accent-soft` 深色档 L*≤30 与页面底（L*≈29）同亮度，深色下选区=隐形；
  - 百分比数只允许写在 `tokens.css::selection` 注释引用的行号处（Gitea light/dark 两档），不在组件里。
- 依据：2026-11-10 用户（暗色拖选不可见）；参考与数值出自
  `knowledge/reference-baseline.md`「文字选区」行（Gitea `base.css:269` /
  `codeeditor.css:177`、Rocket.Chat `codeBlockStyles.ts:13`、LobeChat `chatPanel.css.ts:544`）。
- 机器检查：`test/design-system.test.mjs`（tokens.css 结构断言 + 白字 × accent-solid 5 预设 × 深浅色 ≥4.5 矩阵）。

### 2.30 「明面容器」在深色下必须比所在底更亮（必须）

- 场景：一切"平铺在页面/卡片上、自身有底色的内容容器"——md 的 fenced/th/行内码、思考块、
  工具块（运行/成功/失败）、用户气泡、状态徽标 soft、失败横幅、引用块等。
- 规则：
  - **必须** 这些容器在深色模式有**显式的深色边界**（`[data-theme-mode="dark"]` 覆盖或主题引擎派生）；
    **必须不** 让深色沿用浅色静态 hex——thinking/tool 块曾有 #fafafa/#f4f4f5（白色块） such 病（2026-11-10 实测修掉）；
  - **必须** 深色底**不得比其所在页面底更暗**（方向向上：`#292828` 页面上的容器 ≥ hover `#2f2e2d`）；
    同向回归锁在 `md-render-contract`（语义块三项 + th 一项）;
  - **必须** 引用既有体系而不是新造值：中性块用 `--color-hover`（深色亮/浅色暗的双向 token）、
    语义块用 `*-soft` 的深色派生（规范 2.26）、用户气泡用 `--color-accent-solid`（白字 AA 由 token 语义保证）。
- 依据：① C213（badge soft 底比页面暗）/ C215（fenced 底 sunken 深色凹陷）——同一族，病根是
  "浅色静态值深色沿用"的系统性缺口（2006-11-10 实测清单：五个 `--color-message-*` 全部无深色值）；
  ② 方向参照（标注级别：观察，非 A 级）：GitHub dark 的 fenced 相对页面上**抬一档**
  （页面 #0d1117 → fenced #161b22）；LobeChat dark 的 message 容器同向。
  koharu 的深色代码面下游走黑（card×80%+black）是它自身主题色系的取向 ——
  **方向类自身别做争议**：本条文的执行依据是我们自己的 C213/C215 实测家族 +
  probe 全清（`evidence/ui-round10/semantic-{dark,light}.png`）；参考方向只作背景，不作条文。
- 机器检查：`pnpm test:md`（语义块换挡断言）、`pnpm audit:a11y`（深色块的对比度）、视觉矩阵。
