## 怎么用

## 2 条文

### 2.1 生成状态由显式事件/标记驱动，禁止用"值不相等"猜语义

- 规则：需要一个"用户改过/系统变了"的判断时，用显式动作产生的标记（entry / 事件），不靠值比较。
- 依据：案例 C071（默认模型跟随——靠值相等猜测导致默认永远跟不上）。机器检查：`pnpm test`（model-follow）。
- 依据：模型默认裁决与来源标注见 `knowledge/architecture/agent.md`。

### 2.2 写操作必须覆盖"无会话"分支，选中态由写实现校正

- 规则：改全局/Agent 级状态时，无会话场景单独取数（默认配置接口），不能只刷新会话 meta；列表刷新时校正选中态（回退默认/最新，清掉指向已删对象的选择）。
- 依据：案例 C085（AgentConfig 改默认模型 + agents_changed 校正）。机器检查：`pnpm test`（agents_broadcast 用例）。

### 2.3 同类 UI 第二次出现 → 立"容器 + 注册项"，不为单个动作加常显特例

- 规则：同一类动作/部件（消息动作条、工具块、状态条项）第二次出现时抽容器，功能只声明元数据（名称/图标/文案/权限）；可见性规则全类统一，反馈期间强制可见，不给"救命按钮"开常显例外。
- 依据：案例 C059、C061、C066（动作条三次返工）、C056/C062（常显特例被用户要求改回）。

### 2.4 悬停控件用 `opacity + pointer-events`，不用 `display:none`

- 规则：悬停显现用透明度开关避免布局跳动；键盘焦点/反馈期间强制可见；触屏（无悬停）常显由统一可见性约定实现。
- 依据：案例 C056（复制按钮 display 跳动）+ frontend-spec §5/§9（可见性契约断言，`pnpm test:ui`）。

### 2.5 生成中的键序是契约：Esc=打断、Enter=steer、↑/↓ 历史方向用测试锁

- 规则：输入历史与队列的方向性不做"读码推断"，写契约测试（↑ 取回、清空后 ↓ 返回、生成中 Enter=插话不发送）。
- 依据：案例 C105（输入历史方向反了）、C107。机器检查：`pnpm test`（composer 用例）。

### 2.6 主保存必须覆盖整张表单；多加载 effect 用函数式合并；脏基线=打开时原始值

- 规则：用户看到整页表单时 primary 保存不得只保存一半；关闭确认要写明脏域；初始基线用打开快照，多个加载 effect 用 functional update 合并。
- 依据：案例 C106（改模型后 footer 存一半仍提示未保存）。机器检查：配置页四态测试（testing 规 2.3）。

### 2.7 流式按 assistant message 分段；`contentIndex` 是消息内序号；工具 running 由执行事件驱动

- 规则：消费 Pi 事件时以 `message_start/end` 为段边界，不做整轮全局槽位；thinking/tool 的 live 各自收口；最终答案取最后一段 text；块序只按到达与段内序号。
- 依据：案例 C107、C111（两次返工后定稿）。机器检查：`pnpm test`（stream-blocks / stream-events 全量映射）。

### 2.8 数值/颜色只进 tokens.css，宽度只进 layout() 纯函数

- 规则：组件不写字面量数值/颜色/宽度；命中区、对比度等可视常量做成可断言数值；每处宽度计算走同一条纯函数与不变量断言。
- 依据：2026-10-18 前端体检（MIN_CHAT 三处各自漂移；丑→可断言数值）。机器检查：`pnpm lint:tokens` + `pnpm test`（ui-layout）。

### 2.9 心跳/超时计时器在动作开始时重置；判丢前先向后端确认

- 规则：任何"多久没动静"的逻辑以"上一事件时间"为基线；发送/打断后立刻重置；判丢前查 `GET …/sessions/:sid` 的 `meta.running`，还在跑给第二窗口。
- 依据：案例 C067（页面静置后发送 10ms 内误报中断）。机器检查：`pnpm test`（心跳用例）。

### 2.10 呈现层不直接消费原始事件流（架构硬约束）

- 界面组件只消费 `run-facts`（纯函数：事件+时钟 → 每会话 running/unread/queued/lastTurn）与消息渲染块（stream-blocks）这两个派生层；任何组件直接 `new EventSource` / 读原始事件属缺陷；
- 列表运行点、完成未读、未来通知/换皮都只能作为 run-facts 的观察者；UI 换皮不动机制（呈现与机制解耦的落实条文）。

### 2.11 前端日志与心跳窗口可注入

- 前端 console 结构化输出 + 批量上报 `POST /api/logs`（pagehide flush；error 必报、info 采样）——同后端 2.10 字段与文件约定；
- 心跳窗口（60s）与轮询间隔（5s）定义为模块常量并允许测试覆盖，契约测试不等待真实时间。
