# README 维护规范

> 角色：开发规范　类型：流程　状态：现行（2026-11-17，Task 0022）
>
> 适用：任何人或 Agent 要改仓库根的 `README.md` / `README.zh-CN.md` / `docs/images/` 时。
> **正文不在这里** —— 唯一正文是 `scripts/readme-studio/MAINTAINING.md`（流程、门禁、5 个反面案例、症状→原因）。
> 本文只做两件事：把入口登记进规范体系；把不可商量的硬约束列清楚。

## 为什么单独有这一条

README 是唯一一份**每个访问者都会看**的产物，却不在任何测试的默认视野里：`pnpm test` 跑代码，不跑文档；
两份版本靠人同步；图不是代码，改代码不会让图变旧——**只有人眼能发现图过期**。

本仓库在这三条上各栽过一次（Task 0022 的 `cases/2026-11-17.md` C218–C221）。

## 2 条文

### 2.1 改文档与改代码分开提交（必须）

- 场景：代码改动导致 README 的某句话/某张图不再成立。
- 规则：**必须**先提交代码，**再**在独立提交里改 README；**不得**在一个提交里混着做。
- 为什么：混在一起时，"这句话是跟着哪次代码变的不再成立"无法回溯。
- 检查：`git log --stat` 里 README 与 `src/`/`frontend/` 是否出现在同一个提交。

### 2.2 改图必须基于当前提交，且提交信息写明基线（必须）

- 场景：重拍或新增 `docs/images/` 下的任何图片。
- 规则：**必须**先确认 main 上没有落在图片 mtime 之后的视觉改动（`ui.tsx` / `tokens.css` / `index.css`）；
  **必须**在提交信息里写"基于 commit `<sha>`"。
- 为什么：C218 —— 7 个 GIF 全部按旧界面拍，用户一眼看出来，全部返工。
- 检查：`git log -1 --format=%cd` 与 `ls -l docs/images/*.gif` 对比。

### 2.3 素材必须来自打桩/演示环境，且先扫凭据（必须）

- 场景：用真实家目录副本做拍摄数据。
- 规则：**必须**让 `models.json` 里所有 provider 指向打桩服务（真实网关会 402，画面里是红色错误条）；
  **必须**在复制真实数据后扫 `sk-[a-zA-Z0-9_-]{20,}` 并把命中文件删掉。
- 为什么：C219（红条）与 C222 之后的清理（13 个会话含真实密钥）。
- 检查：`run.mjs` 拍摄前 ping `/v1/models`；复制脚本里带凭据扫描。

### 2.4 两份 README 的一致性由门禁守（必须）

- 规则：**必须**保留 `test/doc-links.test.mjs` 里的四条断言——章节层级序列一致、语言互链双向、
  **图片集合相同**、以及媒体/GIF/章节/围栏的**下限**。
- 为什么：C221（`git checkout` 冲掉英文版 18 处引用）与"删空仍全绿"。
- 检查：`pnpm test`；活性验证是"制造 4 类缺陷后门禁必须变红"。

### 2.5 每张图都要有人看过（必须）

- 规则：**必须**在交付前逐张看新/替换的图，且看的是"这一帧是不是想表达的那件事"；
  **不得**以"脚本跑成功了"代替。
- 为什么：脚本只保证文件生成，不保证画面正确（白帧、红条、旧界面都是脚本"成功"产出的）。
- 检查：Storyboard 的 `keys/` 关键帧目录；逐张确认。
