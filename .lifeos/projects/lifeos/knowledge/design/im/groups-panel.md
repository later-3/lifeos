> 角色：设计　类型：页面　状态：**已落码**（2026-11-02，Task 0015 · T15；模型 A「分组头 + 括线」已实现）

> [`conversations.md`](./conversations.md)；本文定义两端的**同一套分组语言**（分组头、括线、缩进、折叠），
> 数值按端分别给。设计语言总纲见 [`design-language.md`](./design-language.md)（P-02 新增决定 D10–D13 在其 §7 决策记录）。

## 1 背景与意图

- 现状（真前端 `frontend/src/App.tsx`）：**三列** —— 助手 / 项目 / 会话。第二列只装"助手绑定的项目"，
  与第三列同一个作用域被切成两条窄列（实测 216 + 272 = 488px 只放两行文字和一行标题）。
- 问题：① 同一作用域拆两列，用户要在两列之间来回扫；② 列多 → 收起/展开图标多（3 个）；
  ③ 对话区的横向空间被挤。
- 目标（用户 2026-10-30）：**合并成一个面板**，但"合并设计需要有观感上、设计规范上的考量"，
  不是简单把两块拼起来。风格仍走现在的**简易模式**（不带主题风格的那一套），风格升级后面单独议。
- 主操作：进入对话。次操作：折叠/展开某个项目组、进入项目空间。
- 明确不做：改路由语义、改后端层级（`session ∈ Agent × Project` 不变）、两套前端并存。

## 2 数据

| 实体 | 字段（行上呈现） | 来源 | 空值/长值 |
|---|---|---|---|
| 组（Project） | 项目名 + 会话计数 | `GET /api/agents/:id/projects`（`name` 由目录名派生） | 无会话 → 空态行；名可截断（手机） |
| 行（Session） | 标题（缺 → `id.slice(0,8)`）+ 活动时间 + 预览 | `GET /api/agents/:id/sessions?project=` | 无标题走兜底；预览只在双行模式 |
| 状态 | 未读数（绿徽标）、运行点（脉冲）、失败点（红） | `status-map.ts`（`run-facts` 派生） | 未读 0 不渲染徽标 |

## 3 关系

- **Agent 1:N Project，Project 1:N Session** —— 这正是"层次面板"的形状；
- 表达：**分组头（section）= 项目**，**组内行（row）= 会话**，**括线 = 从属关系**（§5.1）；
- 助手列（第一列）不变；选中助手 → 第二列整组重取（现有联动 `App.tsx:801` 不动）。

## 4 用户任务

1. 在**同一块**里选定项目下的对话（不再跨列扫）；
2. 关掉不相关的项目组，让列表变短；
3. 一眼看出"这条对话属于哪个项目"（滚动中也要能看出来 → §7 模型差异点）。

## 7 两个候选模型（请拍板）

两个模型都满足"合并 + 简易风格"，差别只在**从属关系画不画出来**。

### 模型 A · 分组头 + 括线（Zulip 式，推荐）

```
┌ 对话 ─────────────── 300px ┐
│ ▾ lifeos-clone        6    │  ← 分组头 32 / 15 / 600
│  ╭─                    ●    │  ← 括线 1px，宽 8，圆角 4
│  │ 合并面板契约        3m   │  ← 行 32 / 13.5，缩进 12
│  │ 层级结构讨论       6h    │
│  ╰─                        │
│    ＋ 新建对话              │
│ ▸ studio-blog         3    │  ← 折叠的组：只剩分组头
│ ▾ notes               1    │
│  ╭─                        │
│  │ 层级与飞轮         1d   │
│  ╰─                        │
└────────────────────────────┘
```

- **返回/系统返回**：桌面不适用；手机沿用 conversations.md 的层叠语义（本模型不改）。
- **焦点**：分组头是 `button` + `aria-expanded` + `aria-controls`；Tab 顺序 = 分组头 → 组内行；
  折叠时组内行从 Tab 流移除。
- **滚动**：整列一个滚动容器；**不吸顶**（本轮）。滚动到组中部时，归属靠**括线还在**读出来。
- **状态保持**：折叠状态存 localStorage 单键；选中态用 URL 参数（`agent/project/session`）不变；
  刷新后回到同一对话。
- **溢出**：240px 窄栏时括线区仍可容（8px）；长标题 truncate（手机）。
- 代价：多两个 1px 装饰元素；组内只有 1 条时括线显得空（Zulip 同样如此）。

### 模型 B · 分组头 + 缩进（无括线，最省）

```
┌ 对话 ───────────────────────┐
│ ▾ lifeos-clone          6   │
│    合并面板契约         ● 3m│  ← 只靠 12px 缩进
│    层级结构讨论         6h  │
│    ＋ 新建对话              │
│ ▸ studio-blog         3     │
└─────────────────────────────┘
```

- 其余行为（焦点/滚动/状态/溢出）与 A 相同。
- **优势**：实现最小（无装饰元素），列最窄时最省空间。
- **代价**：组与组之间只差 8px 时，滚动中容易误读"这条属于上一组还是下一组"；
  这也是 Zulip 当年画括线要解决的问题。

**推荐 A**：一条 1px 的线不是"花里胡哨"，但它把"这组属于哪个项目"从"要靠记忆"变成"看得见"；
实现代价 = 一个 `span` + 两个边框（无 JS、无动画、无新色）。

## 9 内容与可访问性

- 分组头 `aria-expanded`；`aria-controls` 指向组内列表容器 id；
- 计数徽标 `aria-label="N 条对话"`（不能只让读屏念数字）；
- 折叠箭头 `aria-hidden`，动作名在分组头按钮的可访问名里（`lifeos-clone，折叠分组`）；
- 括线是装饰，`aria-hidden` 或由伪元素实现（不进 DOM）。

## 10 设计验收（可观察行为）

1. 同一项目的对话，左缘比分组头缩进 12px（计算样式断言，不靠截图）；

3. 点分组头箭头 → 组内行消失、`aria-expanded=false`、刷新后仍折叠（localStorage 单键）；
4. 图标栏只剩两个图标，折叠组合从 8 种变 4 种，`test/ui-layout.test.mjs` 全部不变量通过；
5. 1440 宽下对话区比合并前宽 188px（±把手差）；
6. 拖宽分组面板：最小 240 / 最大 440，`MIN_CHAT` 保底不破；
7. 手机 conversations 的分组头/行数值与本文一致。

**与原文的偏差（都已按需求调整，不是自创）**：

1. 原文 §7 模型 A 的分组头含"左侧 16 折叠箭头（`--size-icon`），右侧计数"。落地时把折叠钮与分组名**合成一个按钮**——两个可点目标指向同一动作会让命中区断言与键盘顺序都变复杂。
2. 原文模型 A 的组内有"＋ 新建对话"行；落地把新建会话放到**列底**（与"添加项目"并列），因为 P-02 的另一条要求是"列头只留一个主操作"。
3. 折叠状态原文写"单键数组"；落地用 `{ [projectId]: true }`（只记收起的组，默认全展开）。理由：项目通常 3–5 个，全展开是常态，记"收起的那几个"更省且更直观。
