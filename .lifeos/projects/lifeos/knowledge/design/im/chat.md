# 页面：聊天页（第三列主区）

> 角色：设计　类型：页面设计（IM 版 v2）　状态：**设计中**（demo 已实现，未落地）
>
> 数值来自 [`design-language.md`](./design-language.md)。demo 实现：`Chat()`；样式 `.mhead` / `.taskbar` / `.msgs` / `.composer`。
> 与现行 `knowledge/design/chat.md` 的关系：落地时本文取代那一份的"布局与视觉"部分，消息语义（流式、工具配对、失败九类）仍以现行文档与代码为准。

## 1 职责

**这一屏回答："我和这个同事在这个项目里，现在聊到哪儿、他干到哪一步。"**

- 一个会话 = 一段连续对话；header 命名这段对话，任务条给这段对话的"正在做什么"。
- **不负责**：切会话（第二列 / 同事详情）、切项目（项目分组头 / 项目空间）。

## 2 区域构成

| 区域 | 职责 | 放什么 | 不放什么 |
|---|---|---|---|
| header | 命名这段对话 + 进入同事详情的入口 | 同事头像、**会话标题**、副行（同事名 · 项目名 / 正在输入…）、更多 | 项目统计、任务进度（那是任务条） |
| 任务条 | 这段对话绑定的任务与进度 | 进度条、任务名、类型徽标、当前步骤 | 任务列表、与该会话无关的任务 |
| 消息区 | 内容主体 | 日期分隔、他人气泡、我的气泡、步骤卡、代码/文件卡、工具 chip、时间 | 输入历史、用量统计（属于状态条，未在本轮 demo 范围） |
| composer | 输入 | 输入框（placeholder「输入消息」）、发送键 | 对象复述（"输入给 X…"）、发送按钮文字 |

### 2.1 header 为什么写会话标题而不是同事名

- 桌面三列里，第一列选中行 = 同事、第二列分组 = 项目、第三列 = 这一段对话 —— **会话标题是这一列独有的对象名**。
  写同事名会与第一列重复（同一屏可见范围内同一事实出现两次）。
- 同事身份改为**副行**（`同事名 · 项目名`，meta 12，ink-500）：它是上下文，不是标题。
- 运行中时副行替换为「正在输入…」（success 色），不新增一行 —— 状态属于这段对话，不能把 header 撑成三行。

## 3 数据与关系

| 元素 | 来源 | 规则 |
|---|---|---|
| 会话标题 | `Session.name`（首条消息派生，见后端规范 2.16） | 不截断成无法区分的短串 |
| 任务条 | 该会话关联的任务（`taskId`） | 无关联任务时不渲染整条 —— 不显示空进度条 |
| 消息 | 会话 JSONL → `stream-blocks` 派生 | 气泡只承载 `text`；工具调用、步骤汇报各自成卡，不混进气泡 |
| 时间 | 消息 `timestamp` | micro，ink-500；同一天只显示一次日期分隔 |

- **对象完整性**：一条消息的气泡 + 时间 + 动作属于同一个对象，放在同一 `msg` 容器里，不拆到两侧。
- **工具/步骤自成卡**：与用户气泡视觉区分（白卡 + 左侧尖端 4），不使用终端样式（IM 心智，不是 IDE 心智）。

## 4 状态

| 状态 | 表达 |
|---|---|
| 空会话 | 日期分隔位置显示「还没有对话 —— 输入第一条消息开始」 |
| 进行中 | header 副行「正在输入…」+ 行/任务条进度；composer 发送键变停止（demo 未实现，登记 todo） |
| 失败 | 失败原因 + 重试（不属于本轮 demo 范围；现行 `failure.ts` 九类文案沿用） |
| 离开底部 | 显示「回到底部」浮动按钮（Pi TUI 基线，`specs/frontend-mobile/mobile.md` §4；demo 未实现，登记 todo） |
| 长内容 | 气泡最大宽度 62%，代码块横向滚动不撑破列 |

## 5 交互

- 点击 header 头像/标题 = 同事详情（手机上就是"…"那一屏）。
- 点击任务条 = 项目空间（该项目的任务卡居中）。
- Enter 发送、Shift+Enter 换行、生成中 Enter = 插话（键序契约见前端代码规范 2.5，沿用）。
- 消息区滚动只滚消息区；header/任务条/composer 固定。

## 6 布局与参考

- 三栏中的主列：header 56（单行标题 + 副行）→ 任务条 36 → 消息区（flex，唯一滚动）→ composer。
- 气泡：他人 = surface + 左下尖角 4；我的 = accent + 白字 + 右下尖角 4；宽度 ≤62%；消息间距 8，
  同一发送者连续消息可用 4（demo 暂未区分）。
- 参考：Telegram/飞书（气泡 + 时间 + 系统卡的呈现）；Mattermost/Zulip（三栏结构、消息分块）。

## 7 验收断言

1. header 第一行是该会话标题；同事名只出现在副行，且不重复出现在同一屏的其他位置。
2. 无关联任务时任务条不渲染（不是渲染空条）。
3. 气泡正文 = content 15；气泡内不出现工具结果/步骤列表。
4. composer placeholder = 「输入消息」，不含对象名。
5. 消息区是唯一可滚动区域；header/任务条/composer 固定。
