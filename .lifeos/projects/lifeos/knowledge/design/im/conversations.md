# 页面：对话列表（第二列，按项目分组）

> 角色：设计　类型：页面设计（IM 版 v2）　状态：**设计中**（demo 已实现，未落地）
>
> 数值来自 [`design-language.md`](./design-language.md)。demo 实现：`ColSessions()`；样式 `.chead` / `.grouphd` / `.row`。
>
> **本文处理两个用户提出的具体问题**：① 项目分组头字号太小；② 列头「Frontend 的对话」冗余。
> 两个问题都没在"改个数字"的层面解决，而是先定位区域的职责（§2），再改职责与规范（§3）。

## 1 职责

**这一列回答："这个同事在哪些项目里有过对话，我要接着哪一个。"**

- 内容 = 当前选中同事的**全部会话**，按项目分组（项目是这一列的分区维度）。
- 一行 = 一个会话：**第 1 行标题 + 第 2 行元信息 + 右缘状态**（结构见 `design-language.md` §5.5）。

> **2026-11-02 修订（Task 0015）**：删掉"最后一句预览"。理由：合并后副行要放"对端 + Task + 状态"，
> 预览挤不下；而这一列的职责是"挑哪一条"，不是"回忆聊到哪"。
> 补正：预览**并不额外花 IO**（`listSessions` 已读完整个 `.jsonl`），所以这是**空间取舍**而非成本取舍。
- **不负责**：同事的选择（第一列）、消息内容（第三列）、项目本身的工作台（项目空间，覆盖层）。

## 2 区域构成（先有这张表，"多余"才有判据）

| 区域 | 职责（回答什么） | 放什么 | 不放什么 |
|---|---|---|---|
| 列头 | ① 声明这一列是什么 ② 该列唯一主操作 | label「对话」+ 会话总数 + `＋` 新对话 | **当前同事名**、项目名、筛选器 |
| 项目分组头（section） | 这一组属于哪个项目 + 怎么进去 | 项目名、折叠箭头、会话数、进项目空间的入口 | 会话标题、时间、预览 |
| 会话行 | 一个会话的全部可见信息 | **第 1 行**：标题；**第 2 行**：16px 行内锚点头像（仅 Agent↔Agent 的对端）+ 对端名（仅 A↔A）+ Task 编号 + 运行阶段/失败类别；**右缘槽**：运行脉冲点 / 未读实心点 / 失败红点 / 时间（四态互斥） | 项目名（已由分组头表达）、**最后一句预览**（2026-11-02 删除，见 §1 修订）、按钮 |
| 空态 | 该同事还没有任何会话 | 一句说明 + 主操作 | 假数据、装饰图 |

## 3 两个问题的根因与处理

### 3.1 「Frontend 的对话」为什么是冗余的 —— 根因：列头在复述"选择"

- **冗余的不是这几个字，是"主体"**：`Frontend` 是**选中态**，它已经在第一列用选中底表达，
  在第三列用会话标题上方的同事身份表达。列头的职责是"这一列是什么"，不是"当前选的是谁"。
- **为什么不能只把字删掉**：这个区域还承担两件别人不承担的事 —— ①该列的身份声明 ②唯一主操作
  `＋ 新对话`（它不能挪进行内：行内动作会变成"每条会话都能开新会话"，语义错）。所以**区域保留，表达改为列身份**。
- **处理**：列头文案 = `对话` + 会话总数；`＋` 保留（命中区提到 32，手机 44），加 `aria-label="开新对话"`。
- **同类检查（已比对）**：
  - 第三列聊天页 header 的同事名 = **保留**。它不是复述选择，而是"这段对话的对象是谁"，
    用户看消息时必须要知道对面是谁。（判断标准：**在同一屏可见范围内，同一事实是否已经有一个位置**。）
  - 手机端这一列不存在（模型 B 里同事行直达聊天，列表收进同事详情），所以"列头改为身份声明"是桌面表达；
    手机上同一区域**变成页面标题**，此时同事名要出现（因为第一列不可见）。**同一条规则，不同表面不同表达**，
    这正是需要有规范而不是照搬字面的地方。
- **附带发现（同类）**：composer 占位符原来写「输入给 Frontend…」，同样在复述对象（header 已显示）；
  改为「输入消息」（与 `specs/frontend-mobile/mobile.md` §3 的手机规则一致，桌面同规则更好）。

### 3.2 项目分组头太小 —— 根因：没有档位，不是没有"再大一点"

- 原值 `11.5px / 700 / ink-500`：不在 5 档字阶内，且颜色是辅助色 —— 读起来像"折叠标签"，
  而它其实是**二级导航的对象**（项目 = 工作台）。
- 处理（依据 `design-language.md` D1）：`content 15 / 600 / ink-900`，用 section 级。
  同一行的会话数降到 micro（辅助），不再和项目名抢视线。
- **同类检查（已比对）**：卡片头（"进行中任务"/"近期对话"/"本项目同事"）、字段标签一律是 **label**（meta 12/600/ink-500），
  只有"项目分组头"是 section。**不允许出现第二处 section**（否则层级又被抹平）。

## 4 数据与关系

| 字段 | 来源 | 说明 |
|---|---|---|
| 分组项目列表 | 该同事绑定的项目（有会话才成组） | 无边界的项目不出现（避免空组噪音） |
| 会话 | `GET /api/agents/:id/sessions` | 按项目过滤；顺序 = 最近活跃 |
| 最后一句 | 会话最后一条（文本 / `[进展]` / `[文件]`） | 与第一列同源 |
| 未看 / 进行中 | `status-map` 派生 | 未看按会话；进行中按 `running` |

- **分组计数槽只有一种含义**：始终是"该组会话数"。进行中用**行内绿点**表达，
  不用"进行中 2"替换计数 —— 原来 `runCount ? 进行中 N : list.length` 是一个槽两种语义，
  用户无法比较两个项目（这正是 C126 那一类缺陷：同一位置两种含义）。

## 5 状态

| 状态 | 表达 |
|---|---|
| 分组折叠 | 箭头旋转 90°，组内行不渲染；计数仍显示 |
| 分组内空 | 不出现该组（不显示"（空）"占位，避免制造噪音） |
| 会话选中 | 行底 `accent-soft`，标题 ink-900，预览 ink-700 |
| 会话进行中 | 行首绿点 8px，与标题同一行基线 |
| 未看 | 行尾绿色徽标（micro/700），替代时间 |
| 全部为空 | 列内空态：一句说明 + 「开新对话」 |

## 6 交互

- 点分组头 = 折叠/展开；点分组头右侧 `▤` = 进项目空间（两个动作同一行，用不同命中区区分）。
- 点会话行 = 进入该会话（同时清零该会话未看）。
- 列头 `＋` = 开新对话（默认勾选当前项目，见 `new-conversation.md`）。
- 键盘：分组头可聚焦、Enter 折叠；行可聚焦、Enter 进入（demo 未实现，登记 todo）。

## 7 布局与参考

- 桌面：300 宽列；分组头高 44（与行同一命中区档位；section 的字号更大，不靠高度区分）；
  会话行 56（双行）。
- 参考：Zulip 侧栏 `streams → topics` 两层结构（分区标题 + 行），Mattermost 分组头
  （其 label 派不采用，理由见 design-language D1）。

## 8 验收断言

1. 列头文本不含当前同事名；含该同事会话总数；含一个可点的新对话入口（≥32 桌面 / ≥44 手机）。
2. 项目分组头的字号 = content 档、颜色 ink-900；会话数 = micro、ink-500。
3. 分组头与卡片头的字号不同（section vs label），且全页面 section 只出现在项目分组头。
4. 分组计数槽恒为会话数；"进行中"以绿点表达，不进入计数槽。
5. 任何文本颜色对比度 ≥4.5（含 hover / 选中态）。
