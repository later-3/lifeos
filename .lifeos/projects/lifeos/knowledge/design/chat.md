# 主工作区页面设计（Agent × 项目 × 会话）

> 角色：设计　类型：页面设计　状态：实施中
>
> 统一规范见 `.lifeos/projects/lifeos/specs/frontend-development/frontend-spec.md`；需求见 `.lifeos/projects/lifeos/knowledge/requirements/conversation.md`，架构见 `.lifeos/projects/lifeos/knowledge/architecture/conversation.md`；本页只写本页的数据、关系、交互、状态。
> 页面入口：打开 Life OS 根路径即进入；无独立路由，主页面由 `frontend/src/App.tsx` 挂载。

## 0 背景

- **页面**：主工作区（Life OS 的默认页面）。
- **结构**：左侧三列级联（Agent → Project → Session）＋ 中间聊天 ＋ 右侧面板（文件浏览器 / 完整历史，互斥）。
- **代码**：`frontend/src/App.tsx`、`frontend/src/design/layout.ts`、`frontend/src/SessionHistory.tsx`、`frontend/src/FilePanel.tsx`。
- **使用方**：用户与当前 Agent 对话、切换项目、管理会话、查看文件与完整历史。
- **为什么需要**：这是 Life OS 的主界面；所有 Agent/项目/会话/消息关系都在这里被看见和操作。

## 1 数据

| 实体 | 字段 | 来源 | 说明 |
|---|---|---|---|
| Agent | `id`、`name`、`description`、`avatar`、`defaultProjectId`、`defaultSessionId` | `GET /api/agents` / agent.json | 左列枚举 |
| Project | 全局 `id`、`name`、`path`；绑定目录 | 项目绑定接口 / `project.json` | 第二列；同一项目可被多个 Agent 绑定 |
| Session | `id`、`name`、`updatedAt`、`running` | `GET /api/agents/:id/sessions` | 第三列 |
| Message | `role`、`blocks`（text / thinking / toolCall）、`stopReason`、`errorMessage` | 会话 JSONL / `GET …/entries` | 聊天区与历史 |
| Tool result | `toolCallId`、`isError`、结果正文、耗时 | 会话 JSONL | 挂回对应调用，不按顺序猜 |

- 消息与会话文件是事实源；前端不把本地状态当权威。
- 完整历史的 system 分区来自 Pi 的补丁序列，归属/拼装说明由 `frontend/src/prompt-regions.ts` 提供。

## 2 关系与表达

| 关系 | 基数 | 表达 |
|---|---|---|
| Agent → Project | 1:N（当前 Agent 视角；全局是 N:M） | 第 1 列选 Agent，第 2 列列出它的项目；行内显示会话计数 |
| Agent × Project → Session | 1:N | 第 2 列选 Project，第 3 列列出该 Agent 在该项目下的会话；行内显示相对时间/运行点 |
| Session → Message | 1:N | 主区聊天；消息按时间/内容块渲染 |
| Message → block | 1:N | 文本 / 思考 / 工具调用按 `contentIndex` 有序归并 |
| Session → 完整历史 | 1:1 | 右侧面板按“回合 → 请求/回复”展开 |

- **三列级联**：点上一级，下游整列切换；列之间独立，不互斥收起。
- **默认**只存在于数据层（`defaultProjectId` / `defaultSessionId`），界面不放“默认”徽标；避免与“运行中”绿点语义冲突。
- 项目行只写目录名；会话计数在行内固定槽位；列头不重复行内数据。
- 空态统一 `EmptyState`：图标 + 一句解释 + 主操作。

## 3 用户任务与交互

### 3.1 选择与下钻

- 选 Agent → 自动定位默认/最近 Project → 最近 Session；断开并重订该 Agent 的 SSE（重连即重新快照，不带游标）。
- 选 Project → 切换该项目的会话列；选 Session → 载入消息。
- 点当前已展开的列图标 = 收起；点其它列图标 = 展开；展开前若右侧面板开着，先关它。

### 3.2 会话与项目

- 新建会话（底部“＋新建会话”）= **前端草稿**：只清空聊天区，不建服务端会话、列表不出新条目（Task 0006，2026-10-29；参考 Pi Web `handleNewSession`）。已经处在草稿里时该按钮禁用；无会话时输入框仍可用，首条消息 = 建会话 + 发送。
- 重命名（`session_info`）、删除（确认；删当前会话则定位最近）；运行中删除 409。
- 项目从该 Agent 移除：行内 hover 操作；不移除目录/会话/manifest；默认项目不可移除。

### 3.3 发送与一轮对话

**大步骤固定 4 个（m=4，由我们的状态机定义；工具调用不算步骤）：**

| n/4 | 步骤 | 进入条件 | 子状态（不改变 n/4） |
|---|---|---|---|
| 1/4 | 发送消息 | 用户按发送 | — |
| 2/4 | 受理请求 | 后端 202 / 建会话成功 | — |
| 3/4 | 模型处理 | 受理后开始跑 | 等待模型响应、思考中、执行工具、输出中、重试中 |
| 4/4 | 完成 | done / error / aborted | 完成 / 失败原因 / 已中断 |

- 不从“等待模型”开始，第一步是用户发送；
- 工具调用只改 3/4 的子状态，不增加步骤；
- 4/4 是终止态：工作指示行不再保留，用一行完成状态（`4/4 · 完成 · Xs`）收尾；最终回复是完成结果。

- 发送即进入回复侧；用户消息在右侧，进度/失败在左侧。
- 生成中 Enter = Pi 原生 `steer` 插话（后端同时支持 `followUp`，但当前 UI 不绑定排队列表，不把它写成“排队”）；全局 Esc = 打断（组字中除外）；空会话输入框不禁用。
- 失败归属按步骤显示：发送失败 / 建会话失败 / 受理后中断 / 模型失败（连接·超时·鉴权·限流·5xx·空）/ 工具出错·无结果 / 中断·截断。
- 一轮可有多条 assistant message（工具调用前后各一段）；段内按 `contentIndex`、段间按顺序，旧段思考不跟着整轮转圈；工具执行中由 `tool_execution_start/update/end` 驱动；最终回答取最后一段 text。
- 消息动作条挂在被作用的对象上：复制/重发在用户消息；进度/失败说明在左侧本轮槽。悬停出现，触屏常显，反馈期间保持。

### 3.4 右侧面板

- 文件面板与完整历史互斥；打开一个自动关另一个。
- 面板可拖宽（左缘把手，右拉变小），宽度持久化；放不下就明确降级，不静默吞点击。
- 完整历史：回合 → 请求/回复；请求侧 system 分区标“本次变更/沿用上一轮”；回复侧工具结果按 `toolCallId` 配对；Esc 关闭。

### 3.5 输入框（模型 A：单容器 composer + composer dock）

用户 2026-10-22 选模型 A（对象归属）；2026-10-26 补视觉与 dock 分层（同 Task 0002 复盘）。参考证据：`reference-baseline.md` 的“输入框对象结构”与“composer 视觉”行。

- **结构**：composer 区域 = 一个 dock + 一张输入卡，两者同宽居中（阅读列）：
  1. **composer dock（裸行，无框无底色）**：左区 = **会话累计事实**（`SessionBar`，Task 0008 改名：原 TurnStatusBar 的口径从"这一轮"换成整个会话——轮次/工具调用/生成耗时/输入输出 tokens/平均速度/请求体/上下文，口径源 `session-totals.ts`）；右区 = 输入工具注册槽（`composer-tools`，📷 图片为第一槽，语音/@文件等往里排，按钮同右端钉住）。手机：工具钮回输入卡底行右端，左区无内容时整行隐藏（规则性降级，非特例）。
  2. **输入卡（`composer` 单容器）**：自上而下 = 排队条/调色板（未来横幅同层）→ 附件缩略图行（`composer-attachments`，多图并排）→ 输入行（textarea + 发送/停止钮在同一 flex 行，`items-end`：单行时占位提示与按钮同行，多行时按钮随末行右端对齐）。
- **容器持有唯一的 focus ring**（`focus-within:ring-accent`），聚焦时整个卡一个环；textarea 的 focus 指示在设计系统内**移交**给容器（tokens.css `composer-autogrow` 作用域内 outline:none），禁止出现内层第二个环。调色板不做成与输入框无关的独立浮层。
- **键盘**：Enter 发送、Shift+Enter 换行、IME 组字及 100ms 宽限；调色板打开时 ↑/↓ 选择、Enter 执行、Esc 关闭；空输入 ↑/↓ 浏览**本会话**输入历史（见下）；生成中全局 Esc 打断（组字中除外）。
- **输入历史**（2026-11-05 用户报告后重做，Task 0012）：**从当前会话的用户消息派生**（`frontend/src/input-history.ts` 的 `inputHistoryOf`），不是另记一份流水——所以切会话天然隔离、刷新不丢。↑ = 更旧（最近一条先出）、↓ = 更新（走到底回到空输入）；**已在浏览时输入框非空也继续走**（「空输入」只是进入浏览的条件）；用户一打字即退出浏览；历史属于哪个会话由游标的作用域决定（切会话游标自动作废）。上限 50、按内容去重（口径与三条对照见 `reference-baseline.md` 的「输入历史」行）。
- **生成中**：Enter 走 Pi 原生 `steer` 插话；API 也支持 `followUp`/排队；排队条已实现（`run-queue`，仅可见展示）。
- **高度**：CSS 原生自适应（`composer-autogrow` = `field-sizing: content`，不支持浏览器 JS 兜底），下限 = 单行，上限 = `tokens.css` 的 `--composer-max-height`（8 行），超出内部滚动。
- **占位符**：单句；桌面在同行附键盘提示（如“输入消息 · Enter 发送 · Esc 打断 · / 命令”），**禁止**用 `\n` 排版多行说明；手机只写“输入消息”（mobile.md §3）。
- **按钮**：发送/停止 = 主操作，手机桌面均 ≥44（IconButton `xl`），圆形（`full` 档），随末行右端对齐，不设独立底部行。
- **草稿**：按会话（或待建会话的 Agent+项目）归属；发送失败回填，不静默丢弃。新建会话的草稿按“助手+项目”各一份，跨项目互不影响；刷新带 `?agent&project`（无 `session`）回到草稿，无参数仍打开上次会话。草稿态斜杠命令置灰并提示“发送后可用”，手敲命令被拦截（不当消息发出）。首条消息被明确拒绝（非 2xx）时删除刚建的会话并退回草稿；网络错误不删（不知道是否送达）。
- **可访问**：textarea 必须有 `aria-label="输入消息"`；placeholder 不作为唯一可访问名；调色板行在手机 ≥44。
- **未来扩展**：排队、通知横幅进输入卡容器；新输入工具加进 dock 右区注册槽，不改其他区域排版。

## 4 布局

### 4.0 对话区（2026-11-02 用户拍板，Task 0014）

**一句话**：对话区往社交软件靠（头像 + 名字 + 时间 + 左右分侧），但保留"过程可展开"；主对话区与抽屉（PeerPanel）**同一套渲染**，不为抽屉写第二套。

| 要素 | 规则 | 依据 |
|---|---|---|
| 头像（用户侧） | **你本人**，不是 Agent。数据源 `/api/profile`（`~/.lifeos/config/profile.json` + `profile-avatar-*`）；没设图片就首字母色块（accent 底） | 用户 2026-11-02：「用户是我，不是 agent」 |
| 头像（助手侧） | 当前 Agent 的 `AgentAvatar`（图片优先 / id 派生首字母） | 现有组件，不改 |
| 左右分侧 | 用户消息**整块靠右**、助手固定靠左；但**头部内部顺序两边一致**：`头像 · 名字 · 时间`。用 `justify-end` 靠右，**不用 `flex-row-reverse`**。群聊时"只有自己发的话在右" | 用户 2026-11-02「像微信，发起方始终在右」+ 同日晚些时候指出"14:51 Xu Later 头像"读起来反了：`flex-row-reverse` 把 `头像·名字·时间` 反转成 `时间·名字·头像`，而时间在最前不符合"谁说的→什么时候"的阅读顺序 |
| 名字 + 时间 | 每条消息头部一行：**头像 · 名字 · `HH:MM`**（顺序固定，不随左右分侧反转）。正常消息的时间只在头部出现**一次** | 同上 |
| 用户显示名 | 取 `/api/profile` 的 `name`；**用户可自行改写**（现为 `xu`）。`id` 与 `name` 分离：改名不改 id（`knowledge/architecture/identifiers.md`） | 用户 2026-11-02：「就是 xu 就行了」 |
| **回复的两条 bar**（Task 0008） | 一条助手回复 = `头部 → ResponseBar → 正文 → MarkBar`。<br>· **ResponseBar**（正文**上方**，与主线同位置）＝**这一轮**的过程入口：工具次数/耗时/tokens + 进行中状态 + 回合结论；点开看完整过程（过程块在 bar 内部，不被冲掉）；与头像**同时出现**（占位消息就渲染头 + bar，等待态呼吸）；折叠态**按 session 持久**（`lifeos.response.<sessionId>`）；<br>· **MarkBar**（正文**下方**）＝这条消息上的批注表格（6 列：序号 \| 被批注的原文 \| 用户的话 \| 语气 \| 发送的信息 \| ✕），默认折叠、有批注就常驻；无批注不渲染 | 用户 2026-11-05：「response bar 是在正式回复**上面**的，就跟我们当前的主线的页面一样。而在正式回复**下面**的是 markbar」 |
| **会话累计不重复** | 累计指标（轮次/工具/耗时/token/速度/请求体/上下文）**只在 SessionBar 一处**出现，回复的 ResponseBar 里不许重复；反之回合级事实也不进 SessionBar | 同一份数字两处出现，改一处忘另一处就会自相矛盾 |
| **批注高亮与打开**（Task 0008） | 高亮**常驻**（CSS Highlight API，名按块隔离 `anno-<markId>--<messageId>:<blockIndex>`，兄弟块互不擦除）；**单击高亮的文字** = 展开该处批注（重叠的多条一起展开），再点收起；**hover 不弹卡**（用户 2026-11-05 裁决）；**拖选 = 选中即复制**（Task 0013，2026-11-07：新建批注的草稿框已临时关闭 `ANNO_DRAFT_ENABLED=false`，等 T11 重做入口） | 用户 2026-11-05：「只能是点击 mark bar 里面的条目时，展示它对应的标注信息」+「单击高亮的标注文字，也应该出现标注框的」 |
| **选中即复制**（Task 0013） | 对话区域（`<main>`）里**拖选 / 双击 / 三击松手即写剪贴板**，无需 Cmd+C；成功的提示是选区**上方 8px、水平居中**的深底胶囊「已复制 · N 字」，停留 **1000ms**；界面件（消息头 / 过程摘要行 / 动作条）`select-none`，不混进剪贴板；左侧列与输入框不在范围；在已有选区里单击不重复复制 | 用户 2026-11-05「跟 Pi 一样，选中之后自然就复制了」+ 2026-11-07 在原型 `tools/copy-demo/` 里选定位置/样式/文案/时长（决策 D0–D6 见 Task 0013 的 `01-background.md`） |
| **过程条**（ResponseBar 的统计行） | 一轮完成后，中间的工具/思考折成**一行统计**：`14 次工具 · 2 分 31 秒 · 38.2k tokens`。点开 = 现有完整过程（每个工具块还能再展开） | 用户 2026-11-02 |
| 过程条**不做摘要** | **只数事实**（工具次数/时长/token），禁止出现"总结/摘要/概要"式文字，禁止为此额外调模型 | 用户 2026-11-02：「你怎么搞摘要呢 你没办法搞摘要啊」 |
| 过程条视觉 | 极轻量：无边框、无底色块、一行浅灰文字（`text-meta` + `ink-500`）；**宽度 = 对话列宽，左右边缘与正文对齐**；展开指示用旋转箭头 | 用户 2026-11-02：「跟 turnstatusbar 一样，没有什么边框」；同日改口（Task 0004）：「统一到对话列的宽度」——原写法 `max-w-bubble`(720) 在列宽 860 时右侧空出 140px 阶梯 |
| **助手侧的宽度（Task 0004）** | 思考卡 / 工具卡 / 过程条 / 过程展开区**没有独立上限**，跟随对话列（`--container-reading`，由宽度滑块控）；只有一个宽度来源 | 用户 2026-11-02：「统一到对话列的宽度」 |
| **用户气泡的最大宽度（Task 0004）** | **`min(90%, 56ch)`**：90% 跟对话列（窄列不撑破）、56ch 跟字号（宽屏不出现一行 100+ 字），两者取小；气泡按文字长度自适应（短消息就是内容宽） | 用户 2026-11-02：「不拉满」「根据文字长度调整」「有一个最大宽度」「按屏幕比例，而不是固定的数值」；90% 参考 Open WebUI `UserMessage.svelte:431`，56ch 参考 Vercel ai-chatbot `chat/message.tsx:180`（详见 `reference-baseline.md`） |
| 折叠粒度 | **一轮** = 一条用户消息 → 下一条用户消息之前的全部回复（实测每轮 assistant 消息数中位 6、最大 198；按消息折会碎） | `turn-group.ts` |
| 折叠触发 | 该轮 **≥1 工具 或 ≥1 思考**才折叠；`0 工具 0 思考`（纯问答）**不折叠** | 用户 2026-11-02 |
| 折叠后留什么 | 只留**最后一段 text**（§3.3 既有语义：最终回答取最后一段）；其余全部进过程区 | 同上 |
| 哪些轮次**不折叠** | 失败 / 中断的轮次始终展开（沿用 `forceOpen` 语义） | 现有规则 |
| 进行中 | 过程区**始终展开**（流式看得见）；完成后自动收起 | 用户 2026-11-02：「响应过程中一直动态增加」 |

**两个滑块（显示设置，顶部「完整历史」「文件面板」右侧）**：

| 滑块 | 范围 | 语义 |
|---|---|---|
| 内容宽度 | 专注（视口 1/3，地板 360px）→ **视口宽** → 铺满（`none`） | Obsidian 专注模式 ↔ 取消上限；写入 `--container-reading-width`。**滑块终点是视口宽不是 860**：终点取 860 时整段行程只有 548→860，858 之后会直接跳到铺满（2026-11-02 用户实测 bug） |
| 字号 | **85%–200%**（默认 100%） | 整组字阶等比缩放（写入 `--text-scale`，每档 `calc(base * scale)`），**不改单个 px**；200% 是用户 2026-11-02 定下的上限 |
| 头像随字号 | `avatarSizeOf(22, scale)`：随放大、不随缩小（字小保可识别）、上封 1.6× | 用户 2026-11-02：「纯字号变大了，而头像没跟着一起变，就有点畸形」 |

- 两者都落 `localStorage`（`lifeos.displayPrefs`），坏值回默认不抛；
- 弹层点外面 / Esc 关闭；「恢复默认」一键回 860px / 100%。

## 4.1 移动端

完整规则见 [`mobile.md`](../../specs/frontend-mobile/mobile.md)，本页只写差异：

- 手机（<640）只保留**单主列**消息 + composer + 状态条；不并排三列。
- 会话页 header 左侧是**返回项目**：打开导航并停在项目级；无会话时才是“打开导航”（助手级）。
- 导航页：助手 → 项目 → 会话；选助手/项目只进下一级，选会话才关闭；系统返回/右边缘向左滑一次退一层。
- header/status/composer 固定，只有消息区滚动；`visualViewport` 处理键盘；顶部/底部安全区由 `pt-safe`/`pb-safe` 处理。
- 离开底部时消息区显示“回到底部”箭头，点击回到最新并恢复跟随。
- 状态条保留步骤/耗时；tokens/context 用紧凑指标 + 图例按钮，空间不足时收起次要项。
- 导航/列表行、操作按钮触控目标 ≥44；hover-only 动作在触屏常显（文件页签关闭必须常显）。
- 完整历史/文件面板全屏，header 有返回/关闭且按钮在视口内；焦点陷阱/Esc/滚动锁与配置 sheet 共用。

## 7 设计验收

- 三列级联选中态正确，切 Agent 后下游列重置到默认/最近；URL `?project=` 深链接不被“上次会话”顶掉。
- 列收起/展开成本恒为 44px；拖宽方向正确；刷新后宽度保持；窄窗不压破聊天。
- 发送即出现左侧本轮槽；失败在左侧归属到具体步骤；用户消息动作条只在悬停/触屏/反馈期可见。
- 无会话时修改 Agent 默认模型，头部 meta 立即显示新模型；有会话时：没 `/model` 覆盖 → 跟随有效默认并随 Agent 配置更新；用过 `/model` → 始终显示覆盖模型，之后改默认也不变。
- 空会话输入框可用；首条消息自动建会话；输入法组字中的 Enter 不发送。
- 右侧面板互斥；完整历史工具结果按 `toolCallId` 配对，不出现“永远执行中”。
- 手机：会话页可见“返回项目”；导航选会话关闭；系统返回逐级退；离开底部出现回到底部箭头，点击后恢复跟随。
- 输入框：composer 只有一个 focus ring；调色板/未来横幅在容器内；textarea 有可访问名；自动 1–8 行；空输入 ↑ 取回**本会话**最近一条、连按 ↑ 逐条更早、↓ 逐条回来并回到空输入；**切到另一个会话后 ↑ 只能取到那个会话自己的话**；手机 placeholder 只有“输入消息”，调色板行 ≥44。

## 失败提示的可解读性（2026-10-26）

- 失败块显示**时刻**（本地 HH:MM）与原始原因；不是最后一条的消息额外标「历史记录」。
- 为什么要有：2026-10-26 出网到模型网关的那几分钟里，两个 Agent 的会话同时超时；失败被写进历史，用户重新打开会话看到红色"超时"块，误以为"一直超时"。没有时刻就无法区分"刚失败"和"此刻正在失败"。
- 判定依据：`/api/runtime` 无运行、输入框不忙时，历史里的红色块就是过去时。

## 运行态的对账（2026-10-26）

- 绿色呼吸点（生成中）由事件驱动，但客户端每 30 秒（页面可见时）拉一次 `/api/runtime` 做对账：
  只收敛"运行中"事实，不碰未读与归属。
- 为什么要有：`done` 事件可能漏掉（后台标签页节流、半开连接、乱序守卫丢弃），而心跳正常时看门狗不会重连，
  绿点就会永久亮着（实测：回合完成 24 分钟后仍在闪）。

## 图片查看器（2026-10-27）

- **入口**：消息里的用户图片、工具图片、附件托盘缩略图，点开都是**页面内浮层**，不新开标签页（用户 2026-10-27 指定；之前是 `<a target=_blank>`）。
- **缩放**：滚轮 / `+` `−` `0` 键 / 底部 `− 100% +` 按钮 / 双击切换（适应↔200%）；范围 0.25×–8×，步长 ×1.5；放大后可拖动平移（钳制规则见 `image-zoom.ts` 的 `clampPan`：没放大不许拖、放大后至少还看得见一半）。
- **关闭**：Esc / 点背景 / 关闭按钮；焦点陷阱、背景滚动锁、关闭还焦点复用 `useDialogFocus`（模态契约，闸 3）。
- **参考**：pi-web 上游 `components/ImagePreview.tsx`（e533d9b）的开合契约（原生 dialog、Esc、点背景、触发器是 button + `cursor: zoom-in`）；**缩放是新增**——上游没有。
- **代码**：`frontend/src/design/image-viewer.tsx`（组件）+ `frontend/src/design/image-zoom.ts`（纯函数，`test/image-viewer.test.mjs` 6 个用例）；控件命中区 44px（手机）/36px（桌面），底座带实底药丸，压在浅色图片上也看得见。
