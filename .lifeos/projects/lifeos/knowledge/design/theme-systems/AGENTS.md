# theme-systems/ — 三个产品的主题系统源码级知识库

> 角色：知识库　类型：**源码级机制分析**　状态：**v1（2026-11-09）**
>
> **为什么有这个目录**：用户 2026-11-09 明确要求——「我们的 UI 必须超越 LobeHub、novu、LibreChat，
> 所以必须基于他们三个进行思考、择优……你必须深挖这三个项目，形成文档，包含他们基于源码是怎么实现的，
> 在主题和布局方面深挖，且需要建立知识库」。
>
> 这里的每一份文档回答四件事：**① 怎么布局 ② 怎么配色 ③ 方案是什么 ④ 怎么实现（代码路径）**。
> 所有结论都带 `文件:行号`；没有可核依据的一律标"观察"，不进规范。

## 什么时候读

- 改主题（token 家族、深浅色派生、主色/中性色自定义） → 先读三份实现，再看 `comparison.md`；
- 改布局（rail / 侧栏 / 列表列 / 设置页） → 读各自的「布局」节 + `comparison.md` 的布局决策表；
- 要新增一个"我们比他们好"的点 → 先看 `comparison.md` 的"三家都没做好的地方"清单。

## 怎么用（铁律）

1. **先读文字，再读源码**。本目录已经把关键路径与数值摘出来了；只有要核对细节时才去 clone 里看原文件。
2. **引用必须带 `文件:行号`**。写规范/代码注释时引用这里的结论，注明出自哪个文档哪一节。
3. **不复制代码**。只借机制、结构、数值与理由；实现用自己的写法（我们 Tailwind + CSS 变量，他们分别是 antd 派生 / cva+Radix / cva+Radix）。
4. **他们变了就要重核**：每份文档末尾有「复核触发」，参考项目升级时按它检查。
