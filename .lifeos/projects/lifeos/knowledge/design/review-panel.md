# 检视面板（页面设计）

> 角色：设计　类型：说明　状态：**现状**（2026-11-07 起）
>
> 本页是"检视面板"这个**页面**的设计：布局、什么数据、怎么交互、有哪些状态、范围外。
> 系统事实（检视对象在哪、模块分层、数据模型、工具清单）见 [`../architecture/review-mode.md`](../architecture/review-mode.md)——本文不重复。
> 跨页面规则（token、命中区、可见性）见 `specs/frontend-development/frontend-spec.md`。

## 1 背景与意图

- **入口**：对话页工具栏的「检视当前 Task 的改动」按钮（`aria-label`）；打开后检视面板出现在右侧，与文件面板**并存**。
- **用户任务**：在一个 Task 里，对着"这个 Task 的全部改动"逐处看，并在具体行上留下意见；Agent 也能在同一份数据上读写。
- **主操作**：给某段 diff 留一条意见（点行号 / 拖范围 / 悬停 `＋`）。
- **次操作**：回复已有意见、关闭意见、复制意见给 Agent、把意见放进输入框。
- **明确不做**：写代码（本面板只读 diff）、提交/切分支、改 worktree。

## 2 数据

| 数据 | 来源 | 刷新 |
|---|---|---|
| 检视对象（源路径 / 分支 / HEAD / exists） | `POST /api/review/diff` 的 `items[].source` | 打开面板时、点「重新加载」时 |
| 文件清单与 hunks | 同上 `items[].files[]` | 同上 |
| 折叠段展开的全文 | `GET /api/review/blob`（按需要，一次一份） | 用户点展开时 |
| 评论线程（含回复） | `GET /api/review/comments?taskDir=` | 打开时、每次写操作后重读（不做乐观合并） |
| 作者展示名/头像 | `/api/profile`（用户）、`/api/agents`（Agent） | 打开时一次，按 id 反查 |
| 面板宽度比例 | `localStorage`（`lifeos.reviewRatio`） | 拖动时 |

**空值/长值**：没有 worktree → 显式提示"这个 Task 还没有 worktree（约定位置 evidence/worktree）"；目录不是 git 仓库 → "没有可对比的基线"；路径过长中间省略、完整值在 `title`。

## 3 关系

- **1:N（Task → 源）**：固定两类源（项目 worktree / Task 文档），各自分组标题 + 分支 + 基线。
- **1:N（源 → 文件）**：文件卡列表；文件头带类型徽标与 +/-。
- **1:N（文件 → hunk → 行）**：行是锚点单位。
- **1:N（行 → 评论线程）**：同一行可有多条（不同作者 / 不同范围）——**一对多**，不能后写覆盖先写。
- **1:N（线程 → 回复）**：回复缩进一层显示。

## 4 交互

| 动作 | 怎么做 | 备注 |
|---|---|---|
| 起一条意见 | 悬停行 → `＋`；或点行号；或从行号按下拖到末行；或选中文字拖 | 四种入口都落到同一个 `onAddDraft`（范围归一、跨侧退化） |
| 改范围 | Shift+点 | 以当前锚为起点 |
| 写正文 | 卡片内 textarea，**自动保存** | 不需要"保存"按钮（草稿的意义就是随时离开） |
| 改语气 | 卡片里语气按钮（可多选） | 复用 `marks.ts` 体系 |
| 回复 | 卡片底部输入框 + 「回复」 | 提交后服务端把 `awaiting` 交棒给对方 |
| 关闭 | 卡片「关闭」 | 只有提出者或用户本人有按钮；服务端再校验一次 |
| 复制 / 复制全部 | 卡片「复制」/ 面板头「复制全部 N」 | 只复制未关闭的；格式复用消息批注定稿 |
| 放进输入框 | 卡片「发送」 | **只放进输入框，不自动发** |
| 折叠评论卡 | 卡片「折叠」 | 折叠态行末仍显示头像针 |
| 展开/折叠文件 | 点文件头；面板头可全部展开/折叠 | 面板级一份状态，避免两处各说各话 |
| 展开未改行 | 隐藏段上的「↑ N / ↓ N / 全部 N」 | 超过 20 行才给三向，否则只给「全部」 |
| 折叠未改行 | 同一个折叠条上的「折叠」 | 部分展开就给；全展开后折叠条保留（文案变「已全部展开」） |
| 显示已关闭 | 面板头「显示已关闭 N」 | 默认不渲染已关闭的线程 |
| 重新加载 | 面板头刷新图标 | 手工触发，不自动轮询 |
| 键盘导航 | `j/k` 行、`n/p` 块、`]/[` 文件、`{/}` 首尾、`c` 写评论、`?` 帮助、`Esc` | 输入框里不抢键；光标有可见标记 |
| 编辑回复 | 回复行「编辑」→ 内联改 → 「保存」/「取消」 | 作者或用户；服务端 `reply-update` |
| 重开评论 | 已关闭卡片的「重开」 | 误关的退路；作者或用户 |
| 发送（含全部） | 卡片「发送」/ 面板头「全部发送 N」→ 输入框里的 **chip** | chip 可逐条移除；正文不被塞文本 |
| 标记已看 | 文件卡右侧三态按钮 `○ 未看 / ✓ 已看 / ↻ 已变` | 点它不展开文件；写服务端，刷新仍在 |
| 文件树批量 | 面板里「文件树（N 项，x/y 已看）」→ 点目录 | 目录三态 `all/some/none`；一次请求标完该目录 |
| 语法高亮 | 自动（`code` 类文件，展开且 ≤2000 行） | `.md` 不高亮（源码行级 diff）；`.md` 以外的配置类也不猜语言 |
| md 渲染态 | 段控「源码 / 渲染」（只在有 doc 文件时出现） | 默认源码；渲染档按块标色、代码围栏逐行标色 |
| 并排视图 | 面板头「单列 / 并排」段控 | 默认单列；并排时 context 行左右两格都能批注 |
| 换检视对象 | 「检视对象」下拉（面板内）+ 工具栏「选择要检视的 Task」 | 列本 agent×project 的 Task；`●` 有实质改动、`（仅日常）` 只有 daily、`N 条等你` 有评论等用户；切换即重载 |
| 词级 diff | 自动（成对的增删行） | 单列与并排都有；只标改动的词，未改动部分保持原样 |

**键盘/焦点**：所有按钮有可访问名；`＋` 用 `focus-visible` 常显（键盘可达）；浮层气泡在移开/失焦后消失。

## 5 布局

- **三列并存**：助手列 / 会话列 / 检视面板；检视面板**不与文件面板互斥**，放不下时文件面板按需让宽（不改存储值）。
- **宽度**：全部走比例（`design/layout.ts`），换屏严格等比；对话保底 420。
- **面板内部**：头部（计数/复制/开关/展开折叠/刷新/关闭）→ 检视对象条 → 过滤与密度段控 → 内容区（按源分组）→ 评论卡挂在锚定范围的**结束行**下方。
- **密度**：行高按 `text-micro`；代码侧不折行（横向滚动），文档侧折行。

## 6 状态

| 状态 | 表现 |
|---|---|
| 加载中（首屏） | 「正在计算 diff…」+ spinner |
| 加载失败 | 空态卡片：标题「diff 加载失败」+ 原因（不吞错误） |
| 没有改动 | 空态：「没有可检视的改动」+ 说明基线 |
| worktree 缺失 | 分组内提示：约定位置 + "开发类 Task 应先建 worktree" |
| 非 git 仓库 | 分组内提示：没有可对比基线 |
| 评论服务不可达 | 面板顶部错误条 + 写操作禁用（离线不假装成功） |
| 评论为空 | 不显示计数徽标（不是显示 0） |
| 已看进度为 0 | 显示 `0/N 已看`（进度条 0%）——进度是"还有多少要看"，必须有 0 态 |
| 候选还没拉到 | 选择器显示「正在检查哪些 Task 有改动…」（不是空白） |
| 看过之后内容变了 | 该文件显示 `↻ 已变`，顶部统计里多一个 `N 个已变` 徽标 |
| 段展开失败 | 该段下方红字「展开失败：<原因>」 |

## 7 内容与可访问性

- 文案用用户语言：不出现 `taskDir`/`hunk` 这类实现词在主界面（`@@` 行头保留，因为它是 diff 的一部分）。
- 位置头用等宽字体（`path:Lx-Ly`），给人看的中文范围另给（"第 2-4 行"）。
- 状态用词分开：**「已关闭」**与**「等 Agent / 等你回复 / 等谁？」** 是两件事，不合并成一个词。

## 8 范围外

- 手机适配（手机端单独立项）。
- 语法高亮、并排视图、文件树侧栏、Viewed 进度、键盘导航快捷键。
- 在面板里直接改代码 / 接受建议（会写文件，另需设计）。
