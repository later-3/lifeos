# 消息导航条（对话区左缘的竖列刻度）

> 角色：设计　类型：页面/部件特性　状态：**已实现**（2026-11-19 · Task 0020）
> 代码：`frontend/src/views/message-rail.tsx`（渲染与交互）、`frontend/src/api/rail-geometry.ts`（几何纯函数）、
> `frontend/src/api/rail-anchor.ts`（锚点反查）、`src/rail-ticks.ts`（服务端投影）、`GET …/rail`。

## 1 背景与意图

长会话（实测最长 2290 条 entry）里，回看某一轮只能靠滚动条盲拖。竖条回答一个窄问题：
**"这段对话里我读到哪了、别处还有没有我没看的内容"**，并提供一次点击直达。

- 入口：对话区左缘，一条竖向的刻度列（不是顶部/底部横条）。
- 用户任务：① 看见结构（每轮两条、长短代表内容量）；② 悬停时先看一眼再决定；③ 点一下跳过去。
- 明确不做：全文搜索、按角色/工具筛选、跨会话导航。

## 2 一根刻度是什么

| 字段 | 含义 | 来源 |
|---|---|---|
| `id` | 消息 id | 会话条目 |
| `role` | `user` / `assistant` | 会话条目 |
| `chars` | 内容量（UTF-16 单元） | 服务端按消息正文计 |
| `preview` | 预览文本（截断） | 服务端截断 |
| `host` | 回落锚点：这条被过程条折叠时，界面上唯一存在的锚点 | 服务端给出（前端不按渲染规则推） |

**一轮两条**（问一条、答一条），顺序即时间顺序。一条刻度的**长度**表示 `chars`（分段归一化 + sqrt，
见 `rail-geometry.ts` 的 `zipWidthOf`）：用户与 Agent 的字数量级差一个数量级，混算会让一侧全贴下限。

## 3 三个量，一个事实源

用户看到的三个东西必须永远一致：

| 视觉 | 含义 | 派生 |
|---|---|---|
| 高亮条（`data-rail-active`） | 当前读到哪一条 | `resolvedIndex` |
| 滑块（`.rail-band`） | 当前这条在列里的位置 | 高亮行的位置（居中于该行，夹进可视框） |
| 百分比（`data-testid=rail-percent`） | 整段对话里的进度 | `resolvedIndex / (总数 - 1)` |

`resolvedIndex` 有三档来源，优先级固定：**拖动中** → 拖动值；**刚点击/刚跳转** → 跳转锁；
其余 → 正文锚点反查（`railAnchorOf`，按视口中线量 DOM）。

> 2026-11-19 的教训：滑块曾按比例算、高亮按内容坐标算、刻度列只保证"可见"，
> 三者各自正确、合起来漂移 364px。详见 Task 0020 `cases/2026-11-19-e.md`（C312）与
> `specs/code/frontend/code.md` 2.37。

## 4 交互（四角色 × 六状态）

| 角色 | 行为 |
|---|---|
| 悬停（hover） | 条变厚、用 `ink-700`；**不动高亮、不动滑块**，弹预览卡片 |
| 点击（click） | 立刻高亮那一条 + 滑块落到它 + 正文居中到那一轮（长距离直接到位，不用 `smooth`） |
| 拖动（scrub） | 滑块跟指针；刻度列在下面滚（行跟着滑块）；正文按**增量**联动 |
| 当前（active） | `accent` 色 + `ink-900` 描边，宽度仍表示内容量（不跨满） |

**点击的命中规则**：整个列是一个点击面。命中行就用行，没命中（行与行的缝、条右端空白、滑块覆盖区）
就按 `y` 反算最近的一条 —— 用户"看着哪条点哪条"必须成立。

**拖动语义 = 滚动条**：行号 = 按下时的行号 + 指针增量 / 滑块行程 × (总行数 − 1)；
正文用同一个比例。**整列行程 = 整段对话**（实测拖满一列：正文 100% → 0%）。

**松手**：滑块与高亮停在原处（`RAIL_ACTIVE_LOCK_MS`），不弹回；用户自己滚正文（wheel / 触摸 / 键盘）
才交回锚点。

## 5 几何（`rail-geometry.ts`，纯函数可穷举）

| 量 | 规则 |
|---|---|
| 行高 | 24 → 12px 自适应；条数多时**整列可滚**（不压到 2px） |
| 条宽 | 6–32px，`zipWidthOf`（分段 + sqrt） |
| 滑块高 | `viewHeight × clientHeight / scrollHeight`，下限 20px（VSCode `MINIMUM_SLIDER_SIZE`） |
| 滑块位置 | 高亮行居中；贴边时夹进 `[0, viewHeight − 滑块高]` |
| 列滚动 | **最小滚动**：行在可视区里就不动，出去了才滚到刚好露出来 |
| 宽度预算 | `RAIL_WIDTH_MIN/MAX = 24/36`；左缘空白 < 24px 不渲染（1280 左列展开时正好 24） |

## 6 服务端投影

`GET /api/agents/:id/sessions/:sid/rail` → `{items:[…]}`（与列表接口同一包裹）。
`chars` 与 `preview` 在服务端算，前端不做正文解析；`host` 也由服务端给 ——
"轮末回复被过程条折叠"是渲染规则，会变，投影是事实。

## 7 状态与边界

- **流式中**：本轮的第一条 assistant 消息一出现，刻度就多一条（重取点放在本轮第一个流式事件）。
- **未加载的历史**：`ensureFullHistory` 在打开长会话后后台补页（≤20 页，连续 3 次无增长才停），
  否则滑块行程只覆盖已渲染的那一段。
- **窄视口 / 手机**：左缘空白不足时不渲染（不挤占聊天列）。
- **取不回正文的思考**：与竖条无关，属思考卡的 `thinking-unavailable` 路径。

## 9 已知限制

- 单条命中高度受行高限制（12px），低于 WCAG 24×24；真解法是两级导航（见 Task 0020 `todo/todo.md` #3）。
- 拖动一次只能在"已渲染段"内精确落位；未加载区间靠比例表达（`ensureFullHistory` 缓解）。
- 刻度长度按 UTF-16 单元计，含 emoji 时略长（实测差 0.02%）。
