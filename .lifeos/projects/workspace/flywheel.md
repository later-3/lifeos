# 飞轮（共享 workspace）

> 角色：经验　类型：文档　状态：现行

飞轮是可复用的经验：反复奏效的做法、反复踩的坑、以及为什么（协议 §3.1）。本文件只放对**所有 Agent** 都适用的经验。

- **骨架与安装类改动：模板是唯一事实源。** 文档抄模板、代码只做复制，不在代码里另写目录清单。（依据：2026-10-17 案例 C001、C002）
- **安装一次性，启动只校验。** 任何“每次启动都写入”的逻辑，先问一句：它会不会覆盖用户改动？（依据：2026-10-17 案例 C001）
- **设计点先拍板再动手。** 出设计说明（含选项与推荐）→ 用户逐条批 → 才改代码；实现轮只执行已批清单。（依据：2026-10-17 案例 C004）
- **协议、模板、安装副本、代码四者必须同轮对账。** 模板是源，安装副本是运行时；发现副本停在旧设计时先确认源，再同步，不在两份之间“各改一点”。（依据：2026-10-22 案例 C109）
- **规范按作用域加载，模板按优先级选一份。** 规范逐层追加、不覆盖；任务模板只选第一份，不把两种机制混成“覆盖 / 合并”。（依据：协议 §3.3、§3.7、§11）
- **切换 Task 只改指针是假切换。** 每轮开始必须读取会话的 `activeTaskId`，否则界面显示的 Task 与实际加载的说明不一致；切换只影响下一轮。（依据：2026-10-22 案例 C110）
- **运行事实由服务端持有，前端只消费派生事实**：任何"前端以为在跑/在停"都必须走服务端对账，否则状态与真实运行态漂移。（依据：2026-10-24 lifeos 案例 C113；本条跨项目通用）
- **追加型存储必须做引用完整性校验**：parentId 指向不存在的条目时不会报错，只会让数据从"当前分支"上消失；读路径要检测并显式提示（接口字段 + UI 告警 + 日志），不能静默返回空。（依据：2026-10-24 lifeos 案例 C117；本条跨项目通用）
- **事件消费以快照为基线，终态必须绑定回合标识**：不要用自创的游标重放历史事件；重连=重新取快照，旧回合的终态不得改变新回合。（依据：2026-10-24 lifeos 案例 C119；本条跨项目通用）

- **全局 UI 运行态必须带作用域键**：busy/选中/加载中的缓存不能是裸布尔或裸 id；切 Agent/项目/会话先清或换键，异步对账回来后还要再校验"仍在同一作用域"。否则旧状态会去改新会话。（依据：C120）
- **顶级项目不等于做得好**：读源码前先核对参考版本（HEAD 可能已退化）；能借的是它做对的那一小块，并写清"不借什么"。（依据：2026-10-25 lifeos C122）
- **服务端持有事实，客户端只做展示与补偿**：未读、运行中、完成都要有服务端来源；断线/过载时关闭连接让客户端重快照，不静默丢事件。（依据：2026-10-25 lifeos C122）
- **状态聚合要有唯一的语义定义和派生层**：运行、未读、数量在多层级里（会话→项目→Agent）必须由同一份事实派生，不能每层各存一份。（依据：2026-10-25 lifeos C125）
- **计数的层级语义要写成数字例子**：上层的数字是"下层的个数"还是"下层数字之和"，两者在多层级里差别很大，要用例子钉死，并且一个位置只表达一种含义。（依据：2026-10-25 lifeos C126）
