# animlab —— 动画调参台

独立页面，**不需要后端、不需要建会话、不用等回合结束**。

```bash
cd frontend && npx vite --port 5399
# → http://localhost:5399/animlab/
```

## 为什么有这一页

前几轮改呼吸效果，每次都走"改代码 → 起整套实例（worktree + 独立家目录 + 后端 + 前端）
→ 请用户发消息 → 等回合结束"才能看一眼。用户原话：

> 你起一个完整的实例干嘛呢？我还要去发起会话吗？难道？你就单独针对这些特效，我来调，
> 调好了之后就产生一组数据，我们就使用那组数据不就行了吗？

这一页把"看效果"和"跑系统"解耦。所有会动的元素都在这一页，
参数实时生效，调完底部直接给出要写进 tokens 的那组数值。

## 页面上有什么

| 区块 | 对应的真实元素 |
|---|---|
| ① 状态徽标 | 助手行 / 项目行右缘的蓝色数字（`CountBadge` 的 running 态） |
| ② 会话行蓝点 | 列表每行右缘的 6px 点（`data-state-dot="running"`） |
| ③ 呼吸节奏 | ①② 共用的周期与缓动曲线（同一拍子，否则两个节奏互相干扰） |
| ④ 扩散环 | `box-shadow` 外推（不动布局） |
| ⑤ 聊天区转圈 | 「正在执行工具…」前面的 `Spinner` |
| ⑥ 聊天区文字呼吸 | 工作指示文案（「输出中…」）与 `ResponseBar` 的等待条 |
| ⑦ 无障碍 | 系统"减少动态效果"时是否停掉动画 |

预览用的是**真实组件**（`Row` / `GroupHeader` / `SessionRow` / `Spinner`），
所以看到的就是装上去之后的样子。

## 调完之后

页面底部有一块 JSON（并带「复制」按钮）：

```json
{ "badgeScale": 1.06, "dotScale": 1.22, "duration": 2400, ... }
```

把那块发回来即可，不用描述"再大一点/再小一点"。

## 纪律

- 这一页只是调参工具，**不被主应用引用**，不进 bundle（独立入口，只在 `vite` 里按路径访问）。
- 页面里的样式全部是内联 `<style>`，**不写进 `tokens.css`** —— 避免"调参用的临时值"污染产品 token。
- 只有用户确认过的那组数值，才写成 `tokens.css` 的 `@keyframes` + `@utility`。
