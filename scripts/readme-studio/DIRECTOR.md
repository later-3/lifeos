# DIRECTOR · 产品素材的拍摄导演规范

> 角色：工具　类型：规范　状态：现行（2026-11-16，Task 0022 建立；用户口述"导演思维"后成文）
>
> 这份文件回答一件事：**一张产品素材要"演"成什么样才算讲清楚了，而不只是"截到图了"。**
> 它管的是镜头与叙事；`AGENTS.md` 管的是工具怎么跑、有什么坑。

## 为什么有这份规范

第一版素材是"把功能挨个录一遍"，用户看过之后给了判断：

> 「你像主题，就是展示主题如何切换，然后不是每次换主题都要展示那个切换，后面就是不同主题的展示…这样说明了如何切换主题，也说明了不同主题下我们的色彩是怎么样的，这就是导演思维，每个主题你还要标记下是啥主题名。」

这句话里有三条可执行的规则，外加一条元规则：

| # | 规则 | 本质 |
|---|---|---|
| R1 | **操作只演一次**，后续镜头只演结果 | 观众学会操作之后，重复演示是浪费他的时间 |
| R2 | **需要辨认的对象打角标**（主题名、场景名） | 画面自己必须能回答"这是哪个" |
| R3 | **重点区域用焦点放大**，让人知道该看哪里 | 全窗画面里 13px 的字，观众根本看不见 |
| R4 | 流程要固化：新增一套主题 = 按同一份镜头表再加一段 | 否则每次都要重新设计 |

## 镜头表（写这个，不先写代码）

每张素材开工前先填这张表，填不出来就别拍——**填不出来的地方就是还没想清楚的地方**。

```yaml
素材: theme-tour.gif
要说明的事: ① 主题在哪里换；② 八套主题下界面分别长什么样
镜头:
  - n: 1
    演: 打开设置 → 主题下拉 → 点「Gruvbox」
    时长: 5s
    画面: 全窗
    角标: 无（观众正看着操作本身）
  - n: 2
    演: Gruvbox 下的一屏（安静停留，不操作）
    时长: 1.3s
    画面: 全窗
    角标: "Gruvbox · Obsidian"
  - n: 3
    演: Monokai 下的一屏
    时长: 1.3s
    画面: 全窗
    角标: "Monokai · VS Code"
  ...
转场: fade 0.15s
总时长: ≤12s（超出就减主题数，不减单镜停留）
```

## R1 操作只演一次

**规则**：一张素材里，同一类操作只演一遍。第二遍开始只演“结果”。

**为什么**：观众看第一遍就学会了「点这里能换主题」；第二遍再演一次点击，等于用 3 秒告诉他一件他已经知道的事，而这段时间本可以用来看「这套主题长什么样」。

**怎么做**：
- 镜头 1 演完整的操作路径（含鼠标移动、点击、涟漪）；
- 镜头 2..N 直接是结果画面，**不要**再出现打开菜单/下拉/点击；
- 切换用 `xfade`（0.12–0.2s）。太长会显得拖沓，太短观众看不清是换了画面。

## R2 角标：画面自己说明"这是哪个"

**规则**：凡是"多张同构画面并列"的素材（主题、配色、布局、语言），每一张都必须有角标写清它是什么。

**为什么**：八张主题截图并排，没有角标就是八张"看起来差不多"的图。观众无法建立"名字 ↔ 观感"的对应，等于白拍。

**怎么做**：
- 角标**画在页面内**（`position: fixed` 的 DOM 元素），不用 ffmpeg `drawtext`：
  页面内可随主题变化（前景/背景色跟着主题走，永保可读），且不依赖字体文件；
- 位置固定（左下角或右下角），**同一个素材里所有镜头位置一致**——观众的眼睛不用每次都找；
- 文案格式：`<名称> · <来源>`（如 `Gruvbox · Obsidian`、`VSCode 2026 Dark · VS Code`）。

## R3 焦点放大：告诉观众看哪里

**规则**：当一个细节在 1000px 宽的画面里小于约 24px，就必须给它一次焦点放大镜头。

**为什么**：整窗截图里，状态条上的 `↑25k ↓780 ⚡267 tok/s` 是一行 12px 的字。观众在手机上看 GIF 时，这行字只有 3px 高——**等于不存在**。

**怎么做（实测结论，别用另一种）**：
- **用 2x 录制 + 裁切缩小**：`deviceScaleFactor: 2` 录出 2000×1250，裁出目标区域 720×240，缩到 1000 宽。
  实测 13px 正文放大后**清晰可读**。
- **不要用 `element.style.zoom`**：它会让整页重排，画面在放大瞬间"跳"一下；而且只对 DOM 有效，对 canvas/iframe 无效。
- **不要用 ffmpeg `crop + scale` 从 1x 源放大**：1x 源放大 2.5 倍后边缘明显发虚（实测对比图可查）。

**镜头内的编排**：
```
1. 全窗画面（建立上下文：这是界面的哪一部分）
2. 焦点放大（看清细节）—— 停留 ≥1.2s
3. 回到全窗（可选，让观众知道"刚才看的是这里"）
```

## R4 流程固化：新增内容 = 加一段，不重新设计

新增一套主题 / 一个新功能，**不改规范，只加镜头**：

| 场景 | 动作 |
|---|---|
| 新增一套主题 | `storyboards/theme-tour.yml` 的 `shots` 里加一项 `{ name, preset }` |
| 新增一种语言（未来） | 同一张镜头表换成语言维度，R1/R2/R3 全部继承 |
| 新增一个功能 | 先填镜头表；如果它不属于"操作/结果/多例并列"这三类之一，回来补规范 |

## 自检清单（每条都要过，不过就重拍）

| # | 检查 | 怎么查 |
|---|---|---|
| 1 | 正文在最不利情况下仍可读 | 抽 1 帧，把画面缩到 390px 宽（手机）；正文应仍能认出主干 |
| 2 | 没有失败提示 / 红色错误条 | 逐帧看（这条栽过：打桩服务挂了，画面里是红色的"模型调用失败"） |
| 3 | 没有凭据、没有内部用语（`data-testid`、`demo-model`） | 搜画面文字 |
| 4 | 需要辨认的对象都有角标 | 对照镜头表 |
| 5 | 操作只演一次 | 数一数同一类操作出现几次 |
| 6 | 单文件 ≤10MB（GitHub 上限）、总量控制 | `ls -lh` |
| 7 | 时长与镜头表一致（±10%） | `ffprobe` |

## 素材的类型学（不同类型的素材各有侧重）

| 类型 | 例 | 重点手段 | 不需要 |
|---|---|---|---|
| **操作演示** | 发消息、插话、批注 | 光标 + 点击涟漪 + 关键帧停留 | 角标（观众在看操作） |
| **多例并列** | 主题、配色、语言 | 角标 + 等长停留 + 统一转场 | 操作演示 |
| **细节强调** | 状态条、token 数字、失败归因 | 焦点放大（2x 裁切） | 全窗长镜头 |
| **跨区流转** | 派活回流、检视评论回 Agent | 两段录制 + 转场（表达"从这到那"） | 角标 |
| **静态形态** | 设置页、文件树、手机布局 | 1440 宽静态图（清晰度优先） | 动画 |

> 一张素材可以同时是"操作演示 + 多例并列"（主题素材就是这样）：**镜头 1 是操作，镜头 2..N 是多例并列**。
> 这就是 R1 的实际用法——不是"不要演示操作"，而是"操作只演一次"。
